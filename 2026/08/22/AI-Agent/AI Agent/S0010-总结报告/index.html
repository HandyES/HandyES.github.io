生成时间：2026-08-20（第10课完成触发） | 覆盖范围：RAG检索增强与Agent记忆（知识层） | 项目进度：10/22课

一、阶段知识脉络梳理

1.1 知识图谱

1.2 知识递进关系

本单元的五课构成一条"检索质量持续升级"的主线，每一课解决前一课遗留的瓶颈：

课次 解决的瓶颈 遗留给下一课的问题
第06课 “能检索”——三阶段流水线+向量库 原始query直接检索召回率低
第07课 “检得准”——分块/混合检索/重排 检索策略固定，无法适配query多样性
第08课 “查得对”——查询理解/多路/图检索 每次会话从零开始，不认识用户
第09课 “记得住”——跨会话记忆/遗忘/冲突 各模块独立，检索决策僵硬
第10课 “会决策”——Agent自主检索+自我纠正+可评估 模块仍是进程内函数，未服务化

本单元的质变：第6-8课是"管道优化"思维（RAG是被动的数据通路），第9课引入时间维度（跨会话状态），第10课完成范式转换——检索从"必经步骤"变为"Agent的推理对象"。这正是Naive RAG→Agentic RAG的分水岭。

1.3 核心知识点掌握度评估

知识点 深度要求 自评要点
InfoNCE损失/HNSW算法 必须掌握 能推导对比学习目标函数、解释分层图搜索复杂度
RRF融合/重排序复杂度 必须掌握 能推导1/(k+rank)融合、分析Cross-Encoder O(n×L²)代价
HyDE向量空间分析 必须掌握 能解释假想文档为何比原query更接近答案分布
三类记忆数学模型/遗忘曲线 必须掌握 能写出M(t)=M₀·e^(-t/τ)并论证τ选择
CRAG三级评估 必须掌握 能设计score函数并论证θ₁/θ₂阈值调优方法
Self-RAG反思token 必须掌握 能列出四类token并区分与Reflexion的粒度差异
Long-Context vs RAG矩阵 必须掌握 能用四维矩阵+成本数据论证选型
LLM-as-a-Judge偏差校正 必须掌握 能识别四类偏差并部署校正措施
GraphRAG/记忆框架生态/MinerU 知晓即可 知道何时调用、选型维度

二、技术选型决策矩阵

2.1 Embedding与检索栈选型（第06-07课沉淀）

场景 推荐方案 理由
中文为主+多语言混合 BGE-M3（Dense+Sparse+Multi-vec一体） 单模型三路输出，混合检索免部署双栈
追求检索精度极限 Qwen3-Embedding-8B + MRL维度裁剪 MTEB多语言第一（70.58），MRL支持精度-速度权衡
原型/轻量部署 FAISS v1.15.0 单机够用，EDEN量化器+RaBitQ优化
生产大规模+湖原生 Milvus v3.0 外部Collection零拷贝、SINDI稀疏索引
重排序默认选择 BGE-Reranker-v2-m3（568M） 多语言默认，MIT协议
重排序质量优先 v2-Gemma（9B）/ Qwen3-Reranker-8B 高预算高质量场景

2.2 架构模式选型（第08/10课沉淀）

场景 推荐架构 反面案例
简单事实查询为主 BM25+稠密RRF融合（不上图） 全量上GraphRAG——索引成本浪费（WildGraphBench实证）
多跳推理/实体关系密集 GraphRAG(global)或HippoRAG2 纯向量检索——多跳召回断层
更新频繁的知识库 LightRAG增量更新 全量重建索引——更新窗口期检索质量塌陷
语料<10K token单文档问答 Long-Context直塞 上RAG——过度设计
语料>100K token知识库 RAG（成本低8-82倍） Long-Context——50倍Token成本（56.3% vs 49.0%精度收益不成比例）
跨文档复杂分析 Agentic RAG（多轮+多源+纠正） 单轮预检索——片面答案

2.3 记忆系统选型（第09课沉淀）

需求特征 推荐阵营 代表
通用用户偏好/事实记忆 vector+抽取 Mem0 SDK 2.0（单遍抽取，写延迟-50%）
时序性强/事实频繁更新 graph-first Zep Graphiti v0.29.0（valid_from/to版本化）
记忆需人工审计与分支管理 filesystem-first Letta Context Repositories（记忆=git仓库）
长程对话研究场景 research-grade MemoryOS（LoCoMo +49.11% F1）

⚠️ 延续第09课警示：厂商自报基准须自有评测集复现后再决策（Zep LoCoMo 84%→58.44%修正案例）。

2.4 检索质量评估器选型（第10课新增）

场景 推荐实现 理由
高QPS生产 蒸馏小模型（T5-large级） ~50ms延迟，成本可控
快速原型/低QPS LLM打分 无需训练，300ms+可接受
兜底预过滤 规则启发式（λ₁·sim+λ₂·实体覆盖率） <10ms，零成本

五、第二单元教学反思

5.1 教学效果评估

  • 连贯性强：第6→10课形成"流水线→管道优化→查询理解→记忆→决策合龙"的严格递进，第10课架构图成功复用了前9课全部模块，贯通目标达成
  • 联网更新密度高：本单元5课触发4次重大联网更新（v5.1-v5.5），RAG/记忆生态2026年迭代极快，教学资料时效性维护成本高但必要——MinerU 2.5-Pro、JURY面板、Long-Context成本实证均属决策级信息
  • 数学密度适中：InfoNCE/RRF/HyDE/遗忘曲线四个推导分布在5课中，负载均衡

5.2 学生能力达成度

能力 达成证据
RAG全链路设计 能完成分块→混合检索→重排→生成的完整选型（第07课架构决策题）
查询理解与路由 能按query类型设计改写/分解/图检索路由（第08课）

评估体系设计 能部署四层评估+Judge偏差校正+闭环（第10课第六节）

5.3 下阶段教学重点

第三单元进入协议与框架层，教学重心从"算法原理"转向"工程契约"：MCP的JSON-RPC接口契约、LangGraph的图编程模型、A2A的Task状态机。学生需适应从"数学推导"到"协议语义"的思维切换；第11课MCP v2.0无状态化是2026年重大规范变更，需重点讲透迁移方案。
