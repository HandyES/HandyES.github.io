一、范式演进：从”检索管道”到”知识工具”

时间预算：5分钟（含1.3决策树推导）

1.1 失败场景：为什么”检索一次就完事”不够

沿用前几课的研究助手场景：

失败模式1：无脑检索——用户问”帮我总结一下刚才聊的要点”，Agent仍然去知识库检索一次，浪费2秒延迟和Token成本。教训：不是所有问题都需要检索。

失败模式2：检索了就用——用户问”Self-RAG的反思token有哪些”，检索返回了一篇讲”RAG系统安全”的文档（向量相似度勉强及格），Agent硬着头皮基于它生成答案，产出幻觉。教训：检索结果质量差时，宁可不用、换策略重查，也不能将错就错。

失败模式3：单次检索定生死——用户问”CRAG和Self-RAG在纠错时机上的区别”，第一轮检索只召回了CRAG的文档，答案必然片面。教训：复杂问题需要多轮、多源检索。

这三类失败共同指向一个结论：检索的”何时做、做什么、怎么用”本身应当成为Agent的推理对象——这就是Agentic RAG的核心思想。

1.2 RAG三级演进路线图

用第01课的Harness框架语言描述：Naive/Advanced RAG只有”上下文与工具”功能；Agentic RAG补齐了”验证”（检索质量评估）和”纠正”（三级纠错）两个功能——RAG从管道变成了Harness里的一个受控子系统。

1.3 Agentic RAG决策树（必须掌握）

Agent面对用户query时的完整决策树：

决策树形式化：设状态空间 $S = {s_{answer}, s_{retrieve}, s_{evaluate}, s_{generate}}$，Agent在每个决策点执行策略 $\pi: S \rightarrow A$，其中 $A = {answer_direct, retrieve(k), use, discard, rewrite, terminate}$。与前几课的对比：

架构 决策点数 检索触发方式 终止条件
Naive RAG 0 固定必检 生成完成
Advanced RAG 0（管道参数化） 固定必检 生成完成
Agentic RAG 4个决策点 条件触发（D0判断） 生成完成 或 轮数上限

注意最后一行：轮数上限是工程上最重要的细节。决策树带回边（D3→D1）后系统可能死循环，必须设 max_iterations，超限后降级为”基于现有证据生成+声明局限性”。

二、Corrective RAG：检索质量评估与三级纠正（必须掌握）

时间预算：5分钟

2.1 CRAG架构总览

CRAG（Corrective RAG，arXiv:2401.15884，2024-01）在”检索”和”生成”之间插入一个检索评估器 + 纠正器：

2.2 检索评估器：三种工程实现

评估器回答一个问题：”检索到的文档，能支撑回答这个query吗？”

实现方式 原理 延迟 成本 适用
蒸馏小模型（CRAG原论文） 微调T5-large，输出置信分数 ~50ms 低 高QPS生产环境
LLM打分（2026主流） Prompt让LLM输出1-10相关性分 300ms+ 中 低QPS、快速原型
规则启发式 关键实体覆盖率 + 相似度阈值 <10ms 极低 兜底/预过滤

规则启发式的可计算形式（本课代码实践将实现它）：

$$\text{score}(q, d) = \lambda_1 \cdot \cos(\mathbf{e}_q, \mathbf{e}_d) + \lambda_2 \cdot \frac{|E_q \cap E_d|}{|E_q|}$$

其中 $E_q$、$E_d$ 分别是query与文档的关键实体集合（第08课查询理解层的产出），$\lambda_1 + \lambda_2 = 1$。直觉：向量相似度捕捉语义接近，实体覆盖率捕捉”问的东西文档里真的有没有”——纯向量相似度容易被”同主题但答非所问”的文档骗过（失败模式2）。

2.3 三级纠正动作（必须掌握）

级别 分数区间（示例） 含义 纠正动作
Correct score ≥ θ₁ (如0.6) 检索结果可信 知识精炼（Decompose-Recompose）：文档分解为知识条目，只保留与query相关的条目重组成上下文——去噪，省Token
Ambiguous θ₂ < score < θ₁ (如0.3~0.6) 部分相关 降权保留 + 补充检索：改写query再查一轮，合并结果
Incorrect score ≤ θ₂ (如0.3) 检索失败 换源：query改写（第08课）+ Web搜索兜底；仍失败则诚实声明“知识库无法回答”

两个工程细节：

  1. 阈值是业务调参对象，不是常数。θ₁/θ₂的取值应通过评估集网格搜索（见本课第六节评估闭环）——这正是”评估驱动调参”的典型案例。
  2. Web搜索兜底是有代价的：外部搜索引入延迟（1-3s）、成本、内容不可控风险。生产系统通常给”换源”设预算上限（如每会话最多2次）。

三、Self-RAG：反思token设计（必须掌握）

时间预算：5分钟

3.1 核心思想：让模型”边生成边反思”

CRAG的纠错发生在生成之前（检索后评估）；Self-RAG（arXiv:2310.11511）把反思推进到生成过程之中——模型逐段生成，每段生成前后输出特殊反思token，按需触发检索。

3.2 四类反思token（必须掌握）

Token 触发位置 含义 决策
[Retrieve] / [No Retrieve] 生成段落前 这个段落需要外部证据吗？ 是→发起检索
[Relevant] / [Irrelevant] (ISREL) 收到检索结果后 检索文档与当前段落相关吗？ 不相关→丢弃/重查
[Fully supported] / [Partially supported] / [No support] (ISSUP) 段落生成后 这个段落被证据支撑吗？ 不支撑→重写该段
[Useful: 1-5] (ISUSE) 整体答案后 这个答案对用户有用吗？ 低分→反思改进

与第03课Reflexion的区别：Reflexion是任务级事后反思（整个episode失败后写反思记忆，下次尝试时用）；Self-RAG是段落级过程反思（每段即时判断，粒度更细、纠正更早）。一句话记忆：Reflexion反思”这一轮”，Self-RAG反思”这一段”。

3.4 实现路径的工程权衡（应当理解）

Self-RAG原论文通过微调让模型学会生成反思token（构造含反思token的训练数据，SFT）。对不微调的团队（大多数生产场景），2026年的等价实现是Prompt化反思：

  • 把四类反思token改写为结构化JSON输出：{"need_retrieval": true, "retrieved_relevant": true, "claim_supported": "partial", "usefulness": 4}
  • 用第04课的结构化输出约束（JSON Schema + Constrained Decoding）保证格式
  • 代价：反思占用输出Token（成本↑约30%），延迟随段落数线性增长——精度换成本的明确权衡

（SCMRAG等2025-2026后续工作进一步验证：零样本ReAct推理链+工具调用也能实现同等自纠正，无需特殊token微调——架构师选型时，Prompt化路线已是默认起点。）

四、多模态RAG：图表PDF的处理（应当理解）

时间预算：3分钟

4.1 问题：论文的图表在纯文本抽取中蒸发

研究助手的主要语料是学术论文PDF。一篇典型论文的核心贡献往往在图（实验对比柱状图）、表（SOTA对比表）里——纯文本抽取（第06课默认路径）会把这些信息全部丢失，用户问”该方法在MTEB上比BGE高多少分”时知识库里根本没有答案。

4.2 解决方案：文档解析层 + VLM图表理解

MinerU（OpenDataLab开源，2026年活跃迭代）：将PDF/图片/DOCX/PPTX/XLSX转为LLM-ready的Markdown/JSON，精准剥离图文并保留上下文关联。2026年已发展到MinerU2.5-Pro：在OmniDocBench v1.6上达95.69分（基线92.98），靠数据引擎（多样性-难度感知采样DDAS + 跨模型一致性标注）而非改架构取胜；官方支持MCP协议接入Agent工作流【联网更新v5.5】。选型认知：MinerU是目前学术PDF解析的事实标准之一，与Unstructured、Docling构成主要选项——知晓何时调用即可，不需要会部署。

4.3 多模态检索的统一表征问题

图表描述块与文本块入库后的新问题：用户query”CRAG的纠错流程图”想找的是图本身，但向量库里存的是图的文字描述。工程解法：

  1. 描述块metadata中保存原图引用（{"figure_path": "fig3.png", "page": 7}），检索命中后返回原图URL由前端渲染
  2. 若需跨模态直接检索（以文搜图），需CLIP类统一嵌入模型——知晓即可，研究助手场景下方案1已够用

五、RAG vs 替代方案：架构决策框架（必须掌握）

时间预算：7分钟（含4分钟矩阵推导）

5.1 Long-Context vs RAG：四维决策矩阵

2024年”长上下文杀死RAG”论流行，2026年实证数据给出了清晰的边界。四维对比：

维度 Long-Context（全量塞窗口） RAG（按需检索）
精度 ✅ 较高：全量信息无损送入，无检索漏召回问题 ⚠️ 受检索召回率约束，漏检即答错
成本 ❌ 高：为10M token语料每次查询约$30（Claude价，无缓存）；1000页知识库×每日1000请求场景比RAG贵8-82倍 ✅ 低：只为5-15K token上下文付费，单次查询约$0.01量级
新鲜度 ✅ 换语料即生效（重新拼接） ⚠️ 需重索引（增量索引可缓解，第08课LightRAG）
归因 ❌ 差：答案来自整个窗口，难以标注出处 ✅ 好：可精确引用来源文档，满足审计/合规

2026年基准实证（多文档QA）：Long-Context准确率56.3% vs RAG 49.0%，但Token成本50倍（$0.60 vs $0.012/查询），且长窗口存在Context Rot（注意力稀释，第02课O(n²)复杂度的直接后果）——精度优势并不像宣传的那样大【联网更新v5.5】。

决策规则（必须掌握，可直接用于架构设计题）：

架构师视角：这不是二选一——Agentic RAG天然融合两者：Agent判断”这个问题涉及的语料小”时可以把整个文档塞上下文（D1路由的又一个分支），判断”跨全库问题”时走检索。”RAG死了”和”长上下文万能”都是错的，对的是把两者都当成Agent的工具。

5.2 Agentic Search vs 预检索RAG

对比项 预检索RAG（第06-08课） Agentic Search（本课决策树）
检索次数 固定1次（或管道内固定多次） 0到N次，按需
查询形式 预处理管道产出 Agent动态生成、可中途改写
中间推理 无（管道透明） 有（每步可观察决策依据）
延迟 可预测（P99可控） 方差大（多轮检索）
成本 可预测 上界受max_iterations约束

工程结论：延迟敏感的简单场景用预检索RAG，质量敏感的复杂场景用Agentic Search。研究助手走后者——文献问答的质量要求高于延迟要求。

5.3 LLM Wiki”编译器模式”（知晓即可）

一种新兴架构思想：把知识库视为源代码，定期离线”编译”（用LLM把原始语料整理、去重、结构化为高质量知识文档），运行时直接查询编译产物而非原始语料——类比编程语言的编译期优化 vs 解释执行。优点是运行时零检索延迟、知识已去噪；代价是编译成本高、知识更新有滞后。适合更新频率低、查询频率高的语料（如产品手册）。研究助手的文献库更新频繁，暂不适用——但”预编译思路”在第五单元（第22课AI Coding的知识飞轮）会再次出现。

六、Agent评估体系全景图（必须掌握）

时间预算：5分钟。本节是第03/05课评估内容的体系化收口。

6.1 评估什么：四层评估对象

L4是Agent特有的，也是RAG（L1/L2）与Agentic RAG（需L4）的本质评估差异：同样答对了问题，决策树走3步和走10步的成本差3倍，必须评估。

6.2 LLM-as-a-Judge：方法与偏差校正（必须掌握）

方法：用强LLM替代人工，对答案按Rubric打分或两两对比（pairwise）。优点：可扩展、可复用；缺点：系统性偏差。

四类经典偏差：

偏差 表现 缓解手段
位置偏差 Pairwise对比中偏好特定位置（GPT-4偏第一位，ChatGPT偏第二位） 顺序交换：A/B各评一次，不一致判平局
冗长偏差 偏好更长的答案（哪怕没有更多信息） Rubric显式加入”简洁性”维度；长度归一化
自我偏好 Judge偏爱自己家族模型生成的答案 用异构Judge（GPT判Claude，Claude判GPT）
评分漂移 同一答案不同时间打分不同 固定temperature=0、固定Rubric措辞、版本锚定

2026年研究进展：系统性评测显示单个Judge与人类ground truth一致率仅约87.6%，位置/冗长等偏差合计发生率约0.73；JURY偏差感知面板（多Judge聚合 + 每Judge顺序交换 + 冗长度校正 + 偏差加权聚合）显著优于单Judge；PlanJudge两步法（先让Judge制定评审计划、再按计划执行）进一步抑制推理型Judge的偏差【联网更新v5.5】。工程结论：生产评估至少做顺序交换 + 双Judge交叉，重要决策加人工抽检。

6.3 评估环境设计（应当理解）

评估Agent需要让它的工具”可控可复现”：

环境 做法 适用
Mock工具 检索/Web搜索返回预置语料（第05课Mock框架） 回归测试、CI
沙箱 真实工具 + 隔离环境（独立索引库、测试账号） 集成测试
仿真 真实生产流量回放 / 影子部署 上线前验证

关键设计：评估环境必须固定随机性（LLM temperature=0、检索结果缓存），否则两次评估结果差异无法归因。

6.4 统计显著性基础（应当理解）

评估结论”新版比旧版好”何时可信？

  • 样本量：100条评测集上+3%提升，95%置信区间约±9%——不可信。经验法则：对比实验至少500-1000条，小提升（<5%）需要更多
  • 配对检验：同一评测集上跑A/B两版，用配对样本比较（如McNemar检验）而非独立样本t检验——方差更小，检出力更高
  • 多次运行：LLM输出有随机性时，每版至少跑3次取均值±标准差
  • p值陷阱：p<0.05只表示”差异大概率不是偶然”，不表示”差异重要”——0.5%的提升也可以p<0.05，但可能不值迁移成本。效应量+成本一起看

6.5 评估到改进的完整闭环（必须掌握）

闭环的核心纪律：任何改动必须过评估集回归，评估集持续吸收线上badcase。 第2.3节的CRAG阈值θ₁/θ₂如何定？答案就在这里——网格搜索θ₁×θ₂，在评估集上选端到端准确率与成本的最优帕累托点。

  2. 权重再平衡：LAMBDA_ENT 从0.4调到0.9——检索”CRAG的检索评估器如何纠正”时，doc2的实体覆盖率为0，score大幅下降。思考：纯语义相似度与实体覆盖率各防住哪类失败？（前者防”完全不相关”，后者防”同主题答非所问”）
  3. 关闭换源：WEB_FALLBACK=False——第二个query最终”诚实声明无法回答”。思考：什么业务场景下必须关闭Web兜底？（提示：数据合规、内网隔离）
  4. 解除死循环防护：MAX_ITERATIONS=99 + 构造一个永远ambiguous的query——观察日志爆炸。这就是6.1节”L4轨迹评估”要抓的典型坏轨迹。

层次3：架构决策练习

场景：你的研究助手日均2万次查询，其中70%是”这篇论文的方法是什么”级别的简单事实查询，25%是”对比A方法和B方法的实验设置”级别的跨文档查询，5%是复杂综述请求。当前Agentic RAG全链路平均延迟4.2s、每query成本$0.08，用户投诉延迟。预算约束：延迟P99 < 3s，成本降一半。 给出架构调整方案并说明每一项调整的预期收益与风险。

（参考方向：查询复杂度路由——简单查询走预检索RAG单轮（5.2节对比表）；评估器换规则启发式（2.2节表格）；反思自检仅对高风险查询启用；Web兜底设预算上限。风险：路由误判→简单查询误入复杂路径或反之，需在评估集上量化路由准确率。）

九、参考答案

Q1 参考答案

correct（score≥θ₁）：知识精炼后直接使用——将文档分解为细粒度知识条目，仅保留与query相关条目重组进上下文；ambiguous（θ₂<score<θ₁）：降权保留+query增强补查一轮；incorrect（score≤θ₂）：query改写+换知识源（Web兜底），仍失败则诚实声明。精炼的双重收益：去噪条目提高答案准确率（无关信息是幻觉源），同时压缩上下文长度降低Token成本（生成输入更短）。

Q2 参考答案

四类token：[Retrieve]/[No Retrieve]（段落前决定是否检索）、[Relevant]/[Irrelevant]（评估检索结果相关性）、[Fully/Partially/No supported]（段落后验证证据支撑）、[Useful:1-5]（整体有用性评分）。与Reflexion区别：Reflexion是任务级事后反思——整个episode结束后生成语言化反思记忆，供下次尝试使用（跨episode）；Self-RAG是段落级过程反思——生成过程中逐段即时触发检索与验证（episode内）。口诀：”Reflexion反思这一轮，Self-RAG反思这一段”。

Q3 参考答案

部分支持、整体反驳。支持点：若单次查询涉及的语料<10K token（如单篇论文问答），长上下文确实更简单且精度更高。反驳点：①成本——200万token语料无法塞入单窗口，分批处理意味着每次查询为全部语料付费，实证同规模知识库长上下文方案比RAG贵8-82倍（1000页×1000请求/日场景）；②Context Rot——注意力随窗口变长稀释（第02课O(n²)复杂度与KV Cache约束的直接后果），实证长窗口多文档QA中”needle命中率”随深度下降，且实测精度仅56.3% vs RAG 49.0%，50倍成本只换来7个点的提升；③归因缺失——全量窗口无法给出引用出处，学术助手场景是硬伤。正确架构是Agentic RAG把长上下文作为工具之一（D1路由），而非对立二选一。

Q4 参考答案

①位置偏差——Pairwise中Judge偏好特定位置；校正：A/B顺序交换，不一致判平局。②自我偏好——Judge偏爱同家族模型的输出风格；校正：换异构Judge（Claude判GPT输出）或双Judge交叉。③冗长偏差——新版RAG若恰好输出更长，胜出率可能虚高；校正：Rubric加入简洁性维度/长度分层分析。④评分随机性——单次运行temperature>0时结论不稳定；校正：固定temperature=0并跑3次取均值。⑤统计显著性——58%胜出率在500条上的置信区间约±4.3%，若改进预期只有2%则结论不可靠；校正：扩充评测集或用配对检验计算显著性。

Q5 参考答案（参考方案）

指标设计：检索层——评估器分数分布（correct/ambiguous/incorrect占比，incorrect率突增=索引或查询理解退化）、纠错触发率、Web兜底率、平均检索轮数；决策层——D0直答占比、路由分布、轮数分布（>2轮占比突增=死循环前兆）；成本层——每query Token数、延迟P50/P99、单query成本。轨迹数据：落盘每条决策日志（7.2代码的log即雏形），按query聚类分析坏轨迹模式。案例：告警”延迟P99从3s升到6s”→归因：轨迹数据显示30%查询进入3轮补查→下钻发现ambiguous率从15%升到40%→进一步定位：上周新增了一批扫描版PDF，MinerU解析出的乱码文本导致实体覆盖率普遍偏低→修复：入库前加解析质量校验（OCR置信度阈值），乱码文档走VLM重解析→回归评估集验证ambiguous率回落，P99恢复。评分要点：指标覆盖检索/决策/成本三层、有归因链条、修复后回归验证闭环。

Q6 参考答案（参考方案）

路由函数：def route(query, memory_hits): if has_first_person_ref(query): hits = memory_store.retrieve(query); return MEMORY if hits and hits[0].score > θ_mem else KB+MEMORY_MERGE; else: return KB。合并策略：记忆命中但置信度低时，不独占证据位——将记忆块降权附加在知识库证据之后（复用CRAG的ambiguous档思路），并在生成时显式提示”以下用户历史信息置信度较低，仅作参考”。关键设计点：θ_mem独立于知识库阈值（记忆评分三因子与文档相似度不同分布，第09课）；指代消解需结合对话上下文（”我之前那篇”需要短期记忆中的会话历史参与改写）。常见错误：把记忆与知识库证据平权拼接（用户口误会污染答案）；遗忘消解直接用原始query查记忆（指代未解析导致召回失败）。
