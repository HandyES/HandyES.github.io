一、为什么需要查询优化：查询侧的三个失败模式

第07课解决的三个失败模式（词汇失配/分块割裂/排序单一）都发生在检索管线内部。但还存在一类更上游的问题：用户发出的query本身就不是检索器喜欢的形态。三个典型失败模式：

失败模式1：语体失配（query-ese vs doc-ese）

用户输入：”agent评估”（6个字符的关键词堆）。知识库里的文档是学术摘要：”We propose a comprehensive evaluation framework for LLM-based agents…”（完整学术句法）。两者说的内容相关，但语言形态完全不同——这个问题无法靠第07课的混合检索解决，因为BM25词面不重叠、稠密向量又被语体差异拉偏（第二节数学分析）。

失败模式2：意图失配（隐含结构化约束）

用户输入：”2024年之后的综述论文”。这里”2024年之后”和”综述”是硬过滤条件（metadata filter），不是语义相似度问题。把整个句子当向量查，检索器会把”2024年之前但语义相似的原创论文”排在前面——语义相似 ≠ 满足约束。

失败模式3：视角失配（单一表述/单一跳数）

用户输入：”这批文献的主要争议在哪？”——这是全局聚合型问题，正确答案不存在于任何单个块中，向量检索注定失败。又如”A方法的作者还提出了什么”——多跳推理型，需要关系链（作者→论文→方法），块级相似度无法跨越。

对应的解法：失败模式1 → 查询改写+HyDE（第二节）；失败模式2 → Self-Query（第三节）；失败模式3 → Multi-Query（第四节）+ GraphRAG（第五节）。

二、查询改写与HyDE：向量空间偏移的数学分析（必须掌握）

2.1 Query Rewriting：工程上的第一步

最朴素的优化：让LLM先把query”翻译”成检索器友好的形态。三类改写：

改写类型 输入 → 输出示例 解决的问题
语体改写 “agent评估” → “LLM-based agent evaluation benchmarks and metrics” 失败模式1
指代消解 “它和RAG比呢？” → “该方法（Reflexion）与RAG的性能对比”（多轮场景） 上下文依赖
术语规范化 “大模型微调” → “LLM fine-tuning / PEFT” 中英/口语术语桥接

工程要点：改写由一次LLM调用完成（prompt中给出改写规范），改写失败的兜底是原query直通——改写是增益模块，不能成为单点故障。

2.2 HyDE：为什么”先生成假想答案再检索”有效

**HyDE（Hypothetical Document Embeddings）**的流程反直觉：

用可能包含幻觉的假文档的向量去检索，居然比用真实的query向量更准？这需要数学解释。

2.3 向量空间偏移的分解模型（核心推导）

背景（第06课）：双编码器用InfoNCE在 (query, doc) 配对上训练，只保证匹配对的 $e_q(q)\cdot e_d(d^+)$ 大。训练从未约束”query语言”和”文档语言”在向量空间中如何摆放。

建模：把任意文本 $t$ 的（未归一化）嵌入分解为内容方向与语体方向：

$$e(t) \approx c(t) + s(t)$$

  • $c(t)$：内容子空间分量——“讲什么”（主题语义）
  • $s(t)$：语体子空间分量——“怎么讲”（query-ese：短、关键词、口语；doc-ese：完整句法、学术文体）

两个经验事实：

  1. 短查询：$|c(q)| \ll |s(q)|$——内容信息少，归一化后语体方向占比高；
  2. 语体子空间不对齐：$s_{query}$ 与 $s_{doc}$ 的夹角大（InfoNCE只拉近匹配对的内容，不管两种”方言”的全局对齐）。

展开query-doc相似度：

$$e(q)\cdot e(d) = \underbrace{c_q\cdot c_d}{\text{真信号}} + \underbrace{c_q\cdot s_d + s_q\cdot c_d}{\text{交叉噪声}} + \underbrace{s_q\cdot s_d}_{\text{语体错位项}}$$

  • 交叉噪声项：内容与无关语体的内积，期望≈0，但方差不为0——稀释信噪比；
  • 语体错位项：两种”方言”夹角大，该项小甚至为负。

结论1（偏移的来源）：有效信号占比 $\rho = \dfrac{c_q\cdot c_d}{e(q)\cdot e(d)}$ 随query变短而下降。宏观表现：全体候选的相似度分数被整体压低、top-1与top-2的分差（margin）收窄——排序对扰动更敏感，错排率上升。这就是”语体失配”的数学本质：不是query和文档内容不相关，而是相似度计算被语体噪声污染。

HyDE的变换：$\hat{h} = \text{LLM}(q)$ 是一篇”文档形态”的假想答案，其语体 $s(\hat{h}) \approx s(d)$（同为doc-ese，方向对齐）：

$$e(\hat{h})\cdot e(d) \approx c_{\hat{h}}\cdot c_d + |s_d|^2 + \text{噪声}$$

语体项从”负贡献/噪声”变成正向贡献 $|s_d|^2$。若LLM猜对了主题方向（$c_{\hat h}\approx c_d$），相似度显著抬升且margin扩大。

结论2（误差传播界）：LLM幻觉引入扰动 $e(\hat{h}) = e(\hat{h}^) + \varepsilon$（$\hat{h}^$为”主题正确”的假想文档）。由Cauchy-Schwarz不等式，对任意候选 $d$：

$$\left| e(\hat{h})\cdot e(d) - e(\hat{h}^*)\cdot e(d) \right| \le |\varepsilon|$$

检索排序不变的条件：$|\varepsilon|$ 小于Top-K边界处的分差margin。由此推出HyDE的鲁棒性/脆弱性边界：

  • ✅ 对局部事实错误鲁棒：向量是全文语义的”均值”，假想文档里编错一个基准名称、一个数字，只产生小的 $|\varepsilon|$；
  • ❌ 对主题漂移敏感：LLM完全不了解的冷门领域，生成的假想文档跑偏主题（$\varepsilon$指向另一语义簇），检索整体失效；
  • ❌ 对精确符号查询无增益：”公式(4.3)”这类查询靠BM25精确命中（第07课失败模式1），HyDE生成反而引入噪声。

三、自查询Self-Query：结构化过滤的抽取与执行（工程实践，应当理解）

3.1 机制：自然语言 → {语义查询, 结构化过滤}

Self-Query让LLM把混合意图拆成两部分（输出用JSON Schema约束——第04课Constrained Decoding的直接应用）：

实现三要素：

  1. Schema设计：filter的值域来自索引期注册的metadata schema（字段名、类型、枚举值），LLM只能在合法域内输出；
  2. Prompt注入schema：把字段枚举（如venue: [“NeurIPS”,”ICML”,”ACL”,…]）放进系统提示，杜绝”NIPS”这类非法枚举（或输出后做模糊校正→”NeurIPS”）；
  3. 失败兜底：抽取失败/低置信 → 退化为纯语义检索，不阻塞主链路。

3.2 执行层：预过滤 vs 后过滤（核心权衡）

向量检索与标量过滤的组合有两种执行顺序，召回特性完全不同：

后过滤（Post-filter）：先在全库做ANN取top-k，再丢弃不满足filter的块。

这是后过滤的截断灾难：不是”找不到”，而是”找到了但被过滤掉了，且没有补位机制”。

预过滤（Pre-filter）：先按filter圈定子集（本例100万块→1万块），在子集上做ANN/暴力扫描。

  • 优点：无召回损失，结果精确；
  • 缺点：子集索引维护成本高（每个filter组合一个子索引不现实）；子集极小时ANN退化；部分引擎实现为”先属性扫再向量算”，扫描量=子集大小。

工程折衷——over-fetch策略（最常用）：

配套要求：p需要在线估计（从过滤字段的基数统计近似），并在p过低时直接走预过滤或提示用户放宽条件——这本质上是一个微型查询优化器（类比数据库的谓词下推决策）。

3.3 Self-Query在研究助手中的落地

研究助手的知识库metadata：{year, venue, doc_type, cited_by, method_tag}。典型转换：

用户表述 抽取的filter
“最近两年的工作” year ≥ 2024
“顶会论文” venue ∈ {NeurIPS, ICML, ICLR, ACL}
“高引的” cited_by ≥ 100
“和RAG相关的实证研究” method_tag contains “RAG” ∧ doc_type = “empirical”

四、多路检索Multi-Query与RAG-Fusion：分数归一化策略（必须掌握）

4.1 Multi-Query：用查询宽度换召回

一次生成N个不同视角的查询（同一次LLM调用输出），各自独立检索，再融合：

直觉：单一表述只覆盖语义空间的一个”切面”；一个文档可能不贴近q1但贴近q3。多查询是拿检索宽度（N倍Embedding调用+QPS）换召回覆盖——延迟近似不变（并行），成本线性增长。

4.2 核心问题：跨查询的分数为什么不可比

第07课RRF解决的是同一query、多路检索器的融合；本课是同一检索器、多个query的融合——两种场景共享同一个数学困难：原始分数不可直接合并。

推导：对固定query $q$，语料上分数分布为 ${e(q)\cdot e(d)}_{d\in D}$，其

$$\mu_q = e(q)\cdot \mu_D, \qquad \sigma_q^2 = e(q)^\top \Sigma_D, e(q)$$

（$\mu_D,\Sigma_D$为文档向量的一阶/二阶统计量）。$\mu_q$与$\sigma_q$都随 $q$ 变化：一个”宽泛”query（向量接近 $\mu_D$）的分数整体偏高；一个”偏门”query的分数整体偏低。于是：

同样是0.42分：在宽泛query下可能排第500，在偏门query下可能是第1。跨query直接加权求和分数 = 用不同量纲的数相加。

4.3 三种归一化策略对比（核心知识点）

策略 公式 优点 缺点
min-max $s’=(s-\min)/(\max-\min)$ 简单 离群值敏感（第07课Q4已证：一个20.7分离群摧毁整路排序信息）
z-score $s’=(s-\mu_q)/\sigma_q$ 分布对齐，理论上跨query可比 需要可靠的 $\mu_q,\sigma_q$ 估计（全库统计离线算，小候选集在线估计不稳）；强假设分布形态相似
RRF（排名融合） $\text{RRF}(d)=\sum_q \frac{1}{k+r_q(d)}$ 对分数分布/量纲/离群完全免疫（只读排名） 丢弃分差信息（两个”险胜”和”碾压”贡献相同）

决策规则（工程结论）：

  • 融合方为异构系统或分数分布未知 → RRF（默认选择）；
  • 融合方同源、需要精细加权、且离线有分布统计 → z-score + 权重；
  • 加权RRF是两者的实用混合（RAG-Fusion常用形态）：

$$\text{RRF}_w(d)=\sum_q \frac{w_q}{k+r_q(d)}$$

$w_q$ 给原query更高权重（如原query 1.0、改写query 0.6）——原query是”利用”，改写query是”探索”，探索性证据的投票权应打折。

4.4 RAG-Fusion：Multi-Query + RRF的完整架构

2026年实证支持：SemEval-2026 Task 8（多轮RAG）的优胜系统普遍采用”查询重构（改写/分解/假想文档生成）+ 稠密-词面RRF融合 + Cross-Encoder重排“的组合——即本课+第07课内容的串联，这套范式在多轮对话RAG中仍是当前最优实践之一【2026生态，知晓即可】。

五、GraphRAG：知识图谱增强检索（必须掌握）

5.1 动机：向量检索的两类先天盲区

第四节的Multi-Query仍在”块级相似度”范式内。有两类问题结构性地超出该范式：

  1. 全局聚合型：”这50篇文献的主要研究主题和争议是什么？”——答案需要对全库的聚合视图，不存在于任何单块中。Top-K相似块只是”最像问题的K个碎片”，不是”答案的K个碎片”；
  2. 多跳推理型：”提出Reflexion的团队还用什么方法评估Agent？”——需要走 关系链：论文→作者→其他论文→方法，块级相似度无法跨越两跳。

GraphRAG（Microsoft，2024提出，2026年仍在活跃演进）用离线构建知识图谱+社区层级来补这两块。

5.2 索引构建流水线（五步）

  • ②③抽取：每个chunk一次LLM调用，输出实体及关系（含置信度作为边权重的基础）；
  • ④Leiden算法：对图做层次化社区检测（比Louvain更稳的改进版），同一社区=密集关联的实体群（如”同一个研究主题下的方法+作者+数据集”）；
  • ⑤社区摘要：叶子社区→父社区逐层map-reduce汇总，形成”全局主题的层级视图”。

索引成本估算（架构师必算）：设10k chunks，实体+关系抽取约2次LLM调用/chunk，社区摘要约0.5次/chunk：

$$\text{token} \approx 10{,}000 \times 2.5 \times 3{,}000 \approx 7.5\times10^7 \text{ tokens（索引期一次性）}$$

再加每次增量更新的局部重算——这是GraphRAG最大的落地门槛（5.5节选型矩阵直接回应此点）。

5.3 查询模式：Local / Global / DRIFT / Basic（2026官方四模式）

模式 机制 适用
Local Search query实体匹配 → 图上fan-out到邻接实体/关系 → 关联文本单元组装进上下文 具体实体为中心的问题（”Reflexion的反思记忆怎么更新”）
Global Search 社区摘要 → map（每个社区生成部分答案+置信度）→ reduce（聚合排序） 全局聚合型（”整个语料库的主要主题”）。注意：这是生成式聚合而非检索——没有”取回文档”这一步
DRIFT Search（2026，知晓即可） 先用社区信息锚定全局语境，再局部fan-out遍历——Global与Local的混合，平衡质量与计算成本 需要全局背景+具体细节的复杂问题
Basic Search 退化为标准向量top-k 简单事实查询（图索引不划算的场景）

5.4 PageRank式排序（核心推导）

图检索的关键问题：fan-out出50个邻接文本单元，上下文只放得下10个——按什么排序？ 度数（degree）是query无关的静态指标；GraphRAG系（及HippoRAG系）采用查询条件化的随机游走排序。

PageRank模型：想象随机游走者（random surfer）在图上跳转：以概率 $d$ 沿出边均匀走一步，以概率 $1-d$ 瞬移到任意节点。节点长期访问频率即其重要性：

$$PR(v) = \frac{1-d}{N} + d\sum_{u\in B(v)} \frac{PR(u)}{L(u)}$$

  • $B(v)$：指向 $v$ 的节点集；$L(u)$：$u$ 的出度；$N$：节点总数；
  • $d$（阻尼系数，典型0.85）：继续游走的概率——含义是”每步有15%概率彻底重新开始”；$d=0.85$对应平均路径长度 $1/(1-d)\approx 6.7$ 步；
  • 求解：幂迭代 $\mathbf{PR}^{(t+1)} = M\mathbf{PR}^{(t)}$，收敛速度由转移矩阵第二特征值决定，迭代次数 $O(\log\varepsilon/\log d)$——d=0.85时约几十次迭代收敛到1e-6精度。

Personalized PageRank（PPR）——图检索真正用的算子：把瞬移分布从均匀改为集中于查询命中的实体集 $S$：

$$PR_S(v) = \frac{1-d}{|S|}\mathbb{1}[v\in S] + d\sum_{u\in B(v)} \frac{PR_S(u)}{L(u)}$$

$PR_S(v)$ ∝ 从查询实体出发的随机游走访问 $v$ 的期望频率 → “离查询实体的图上可达性越强、路径越多，排序越高”。这正是HippoRAG系列多跳检索的核心算子（海马体记忆索引理论的工程化）。

与向量相似度的本质区别：向量排序度量”文本像不像”，PPR度量”关系网络上离查询锚点近不近“——后者才能回答多跳问题。

5.5 2026图RAG生态与选型矩阵（知晓即可，联网更新v5.3）

图RAG在2025-2026快速分化出多个流派：

方案 核心特点 强项 弱点
MS GraphRAG 社区层级+摘要，Global/Local/DRIFT/Basic四模式，官方增量索引（update/fast） 多事实聚合最优 索引成本高（社区摘要map-reduce）
LightRAG（HKU，v1.5.x） 双层检索（实体级+主题级），主打增量更新与轻量索引，naive/local/global/hybrid/mix五模式 工程落地、动态知识库 复杂全局问题弱于MS GraphRAG
HippoRAG2 索引期固定边权重 + PPR多跳检索 多跳推理最强（Complex Reasoning基准ACC 53.38） 边权重静态，游走易被”枢纽节点”吸住
LeanRAG（AAAI 2026） 学术新方向（持续演进中） — 尚无生产验证

ACL 2026 WildGraphBench实证结论（架构师要背下来的反直觉发现）：

  • 简单事实查询：BM25仍然很有竞争力，部分场景超过图方法——关键词匹配是事实查找的强先验，别为了图而图；
  • 多事实聚合：MS GraphRAG(global)最优（ACC 47.64），图方法的优势在难任务上才显现。

决策矩阵：什么时候上GraphRAG？

问题形态 推荐方案 理由
精确事实/编号查询 BM25（第07课） WildGraphBench：词面匹配仍是强先验

架构师警句：GraphRAG的索引成本比向量RAG高约2个数量级。正确姿势是查询路由（简单问题走便宜的路）而非全量上图——这正是第10课Agentic RAG”Agent自主决定检索策略”的伏笔。

八、参考答案

Q1 参考答案

出度：$L(A)=2, L(B)=1, L(C)=1, L(D)=0$。第1轮：

  • $PR(A) = 0.0375 + 0.85 \times PR(C)/1 = 0.0375 + 0.2125 = 0.25$
  • $PR(B) = 0.0375 + 0.85 \times PR(A)/2 = 0.0375 + 0.10625 = 0.14375$
  • $PR(C) = 0.0375 + 0.85 \times [PR(A)/2 + PR(B)/1] = 0.0375 + 0.85 \times 0.35625 = 0.34031$
  • $PR(D) = 0.0375$（无入边，只有瞬移项）

第2轮：$PR(A)=0.32677$，$PR(B)=0.17637$，$PR(C)=0.45935$，$PR(D)=0.0375$。

D恒等于 $(1-d)/N=0.15/4=0.0375$：随机游走者只能通过瞬移到达D——D没有任何”被推荐”渠道。检索语境：D对应没有任何文档引用/指向它的孤立实体——即使内容相关，基于图结构的排序永远把它压在底部。工程启示：图检索必须与向量检索互补（孤岛实体靠向量兜底），这正是GraphRAG保留Basic/向量模式的原因之一。

Q2 参考答案

设假想文档 $\hat{h}^$ 主题正确，实际生成 $\hat{h}=\hat{h}^+\varepsilon$。由Cauchy-Schwarz，任意候选 $d$ 的分数扰动 $\le|\varepsilon|$。

  • 局部事实错误（编错基准名/数字）：只改动 $c(\hat{h})$ 的一个小分量，$|\varepsilon|$远小于Top-K边界分差margin → 排序不变。且向量是全文语义均值，细节错误被”平均”稀释；
  • 主题漂移：$\varepsilon$ 是一个指向其他语义簇的大向量，$|\varepsilon|>$ margin → 检索中心整体搬到错误簇，Top-K全错。

必败例子：”XX化工厂2019年技改项目的中标金额”（本地化冷门事实）——LLM训练数据中无此知识，生成的假想文档只能是泛泛的”采购公告模板”，主题已漂移；正确答案靠精确词面（BM25）命中。

Q3 参考答案

由 $\mu_q = e(q)\cdot\mu_D$：宽泛query的向量接近语料中心 $\mu_D$，其 $\mu_q$ 大——所有文档分数整体偏高；偏门query分数整体偏低。直接相加时，宽泛query贡献的是”被整体抬高的一列分数”，等价于隐式给了它远超1/3的融合权重；且这种权重偏差随query对之间的”宽泛度差异”无界增长，纯粹是量纲伪影而非语义证据。

修复方案：

  1. RRF排名融合（推荐）：只读排名，$\mu_q,\sigma_q$被整体丢弃，量纲伪影消失。代价：丢失分差信息；
  2. z-score归一化后加权：$(s-\mu_q)/\sigma_q$ 把每路分数标准化到同一分布再合并，保留幅度信息。代价：需要可靠的 $\mu_q,\sigma_q$（全库统计需离线维护，语料更新要重算；小候选集在线估计方差极大）。

比较：异构/未知分布→RRF（稳健优先）；同源系统+精细调权+有离线统计→z-score。

Q4 参考答案

期望返回 $= k\times p = 8\times0.005 = 0.04$ 块——96%的概率返回空结果（泊松近似 $P(\ge1)=1-e^{-0.04}\approx3.9%$）。

要求期望≥8块：$fetch_k = k/p = 8/0.005 = 1600$ 块。问题：①ANN在1600规模已接近暴力扫描，延迟与内存开销剧增；②fetch硬上限（如256）会截断补偿，仍不达预期；③p再低一个数量级时fetch需求1.6万——指数级恶化。因此工程规则：$p < $ 阈值（经验1%~5%，引擎与SLA相关）时切换预过滤（先按属性圈子集再向量检索），或直接提示用户放宽条件——放大fetch只在p中等（如10%+）时划算。

Q5 参考答案（参考方案）

决策1——单次调用复用：一次LLM调用输出结构化JSON（第04课Constrained Decoding保证合法）：

路由标签、改写、filter、HyDE文档四合一，prompt中给路由判据（含few-shot）。延迟：一次调用≈150-300ms（流式中断可设200ms超时），成本：约400 token/次——满足”≤1次调用”约束。

决策2——HyDE策略：默认关，仅对”开放语义类+query长度<8词”开启（短query语体失配最严重，2.3节 $\rho$ 最低）。开关由路由标签控制，与决策1同一次调用输出（hyde字段为null即关）。P99 800ms预算下，HyDE的额外生成约200ms只在低延迟路径允许。

决策3——路由矩阵：

查询类 路径 默认
事实/编号 BM25精确路（第07课） —
结构化过滤 Self-Query抽取→预/后过滤决策（Q4规则）→混合检索 —
开放语义 改写（+条件HyDE）→混合检索→重排序 未明路由走此路
综述/全局 若已建图：GraphRAG Global；未建图：检索Top-50+LLM map-reduce摘要（降级） —

默认开放语义路的理由：它是四类中召回面最宽、无硬约束损失、延迟可控（≈300ms）的路径；路由错误落在宽路径上损失最小。

决策4——GraphRAG取舍：按5.2节公式，5万篇≈5万chunk（每篇1块摘要）×2.5次×3k token ≈ 3.75×10⁸ token索引成本（GPT-4o-mini级价格约数百美元量级，可接受）+增量更新运维。关键变量是综述型问题占比：若≥10%的用户查询为全局聚合型，值得建图。选型：知识库为论文库（持续增量入库、每日新增）→ LightRAG（增量更新成本低、双层检索覆盖大部分需求）；仅当”跨文献争议地图”类深度分析成为核心功能时再评估MS GraphRAG。图检索作为旁路服务（路由分流），向量检索保持默认主路——WildGraphBench已证明简单查询上图反而吃亏。

决策5——降级策略：LLM超时/失败 → 查询理解层整体旁路：原query直通第07课混合检索+重排序流水线（延迟反而下降，质量回落到第07课水平），qu_degraded=true写入工具metadata供上层Agent与监控感知；连续失败×3进入DEGRADED状态（第07课Q6 FSM复用），期间跳过理解层；恢复探测成功×5回归。红线：Self-Query抽取失败时绝不能把”2024年之后”这类词留给向量检索（会产生看似相关的错误结果）——抽取失败即视为无过滤条件，走语义路并在结果中提示。

Q6 参考答案（参考方案）

要点：①模糊校正用同义词映射表（训练数据里”NIPS”是NeurIPS旧称，高频必处理）；②放宽而非空返回——空结果是用户体验事故，放宽+显式hint让上层Agent能转述”未找到该会议论文，以下是全库结果”；③校正失败的词（如”KDD”不在枚举内）不应硬过滤，降级为语义词并入query。
