第01课：AI Agent历史演变与系统架构总览

课程信息

  • 课程名称：AI Agent系统架构设计
  • 本课序号：01/22
  • 预计学习时间：约50分钟（历史速览25min + 架构总览20min + 习题10min）
  • 项目贡献：基础架构层——搭建Agent系统骨架认知

本课导读

本课分两部分：前半节快速过一遍AI Agent的历史演变脉络（重点关注架构范式的变迁，而非编年史）；后半节深入剖析LLM驱动Agent的系统架构，建立贯穿全课程的技术框架。

本课同时引入贯穿全课程的实战项目——“企业级智能研究助手Agent系统”，后续每课都将为该项目添砖加瓦。

本课还将引入Harness工程概念作为贯穿全课程的顶层框架。Harness工程是围绕LLM模型构建的工程体系，包含上下文与工具、约束、验证、纠正、编排五个核心功能。后续每课都对应Harness的一个或多个功能模块——从本课建立的架构骨架开始，逐步搭建出完整的Harness工程。

第一部分：AI Agent历史演变（25分钟速览）

1.1 三个时代的架构范式变迁

AI Agent的发展可以划分为三个时代，每个时代的核心架构范式发生了本质变化：

下面快速过一遍每个时代的关键节点，聚焦架构决策者需要知道的。

1.2 规则驱动时代：符号主义与专家系统

核心架构：

代表系统：

  • MYCIN（1970s）：医疗诊断，约600条规则，能诊断细菌感染并推荐抗生素
  • DENDRAL（1960s）：化学分析，从质谱数据推断分子结构

架构设计师视角的关键教训：

  • 规则引擎的本质是有限状态机（FSM）——状态空间被规则穷举
  • 致命缺陷：规则数量随问题复杂度组合爆炸，MYCIN诊断600种细菌需要600条规则，无法泛化到第601种
  • 这个教训直接影响了后来Agent架构的设计哲学：用学习替代穷举，用泛化替代枚举

1.3 学习驱动时代：强化学习Agent

核心架构：

代表里程碑：

  • DQN（2013, DeepMind）：深度神经网络近似Q函数，在49款Atari游戏中达到人类水平
  • AlphaGo（2016）：蒙特卡洛树搜索 + 策略/价值网络，击败李世石
  • AlphaZero（2017）：自我对弈学习，无需人类棋谱

架构设计师视角的关键教训：

  • RL Agent的架构本质是马尔可夫决策过程（MDP）的求解器
  • 核心公式——Bellman方程：

Q(s,a)=r+γ⋅max⁡a′Q(s′,a′)Q(s, a) = r + \gamma \cdot \max_{a'} Q(s', a') Q(s,a)=r+γ⋅a′max​Q(s′,a′)

其中 γ\gammaγ 是折扣因子，控制Agent对长期收益的重视程度。

  • 致命缺陷：策略函数是任务特定的——AlphaGo的策略网络只能下围棋，不能下象棋。泛化性 = 0。
  • 关键启示：Agent需要的是通用推理能力，而非特定任务的最优策略。

1.4 LLM驱动时代：通用智能Agent的诞生

范式转变的核心：LLM提供了第一个通用的"推理引擎"。

关键演进节点（架构视角）：

时间 里程碑 架构贡献
2023.03 AutoGPT 首次展示LLM自主分解任务+工具调用+迭代执行的闭环
2023.05 ReAct论文 形式化了Reasoning+Acting交替循环，成为Agent推理的标准范式
2023.10 OpenAI Function Calling 标准化了LLM与外部工具的接口协议
2024.06 Reflexion模式成熟 自我反思闭环成为Agent标配，“行动→评估→改进”
2024.11 Anthropic推出MCP 标准化Agent与工具/数据源的连接协议
2025.03 Google ADK发布 层级化Agent树架构，原生A2A支持
2025.04 OpenAI Agents SDK 原生沙箱、子Agent、MCP一等支持
2026.07 MCP v2.0规范 从有状态双向协议→无状态请求/响应，支持Serverless部署
2026 多Agent协同主流化 Supervisor/Swarm/Hierarchical/Event-Driven模式成熟

架构设计师视角的核心洞察：

LLM Agent与前两个时代的本质区别不在于"更聪明"，而在于架构范式的根本变化：

  1. 决策核心从"特定"变为"通用"：LLM是通用推理引擎，无需为每个任务训练特定模型
  2. 能力扩展从"重训练"变为"加工具"：通过Function Calling和MCP协议，Agent能力可通过添加工具无限扩展
  3. 知识获取从"编码到参数"变为"运行时检索"：RAG让Agent能在运行时获取最新知识，无需重训练
  4. 协作模式从"单体"变为"集群"：多Agent系统让复杂任务可通过分工协作完成
  5. 应用前沿从"对话助手"扩展到"AI Coding"：2025-2026年，Agent技术最引人注目的落地场景是AI Coding——Cursor、Trae、Claude Code等工具将Agent的PDA循环应用于代码生成与审查，形成了Spec Coding范式（第21课详述）。这标志着Agent从"回答问题"进化到"自主完成工程任务"

半节课历史到此结束。 接下来的核心是深入LLM Agent的系统架构。

第二部分：LLM驱动Agent的系统架构总览（20分钟）

2.1 Agent的形式化定义

从架构设计师的视角，一个LLM驱动Agent可以被形式化定义为一个六元组：

Agent=⟨S,A,O,M,π,T⟩\text{Agent} = \langle \mathcal{S}, \mathcal{A}, \mathcal{O}, \mathcal{M}, \pi, \mathcal{T} \rangle Agent=⟨S,A,O,M,π,T⟩

符号 含义 说明
S\mathcal{S}S 状态空间 Agent的内部状态（当前任务、已完成的步骤、中间结果）
A\mathcal{A}A 动作空间 Agent可执行的动作集合（调用工具、生成回复、终止任务）
O\mathcal{O}O 观察空间 Agent能从环境获取的信息（工具返回值、用户输入）
M\mathcal{M}M 记忆系统 短期记忆（上下文窗口）+ 长期记忆（向量数据库）
π\piπ 策略函数 由LLM实现：π:S×M→A\pi: \mathcal{S} \times \mathcal{M} \rightarrow \mathcal{A}π:S×M→A
T\mathcal{T}T 工具集 Agent可调用的外部工具集合（搜索、代码执行、API等）

关键理解：与RL Agent的MDP模型相比，LLM Agent的策略函数 π\piπ 不是通过训练得到的数值函数，而是由LLM通过自然语言推理实现的。这意味着：

  • 策略不需要训练即可使用（零样本能力）
  • 策略可以通过Prompt动态调整（无需重训练）
  • 策略可以解释自己的决策（自然语言推理链）

2.6 Harness工程：贯穿全课程的顶层框架

前面2.1-2.5节从模块视角拆解了Agent系统。本节引入一个更高层的抽象——Harness工程，作为贯穿全课程的顶层框架。如果说前面的六大模块是"零件图"，那么Harness工程就是"总装图"：它告诉我们每个零件装在哪里、起什么作用。

2.6.1 什么是Harness工程

Harness工程（Harness Engineering）是指围绕LLM模型构建的工程体系。LLM本身只是一个"推理引擎"，要让它真正成为可用的Agent，需要在模型外围搭建一套工程框架——这套框架就是Harness。正如马鞍（harness）让马匹的力量得以被驾驭和利用，Agent的Harness让LLM的推理能力得以被可靠地组织和调度。

概念参考：李博洁《深入理解AI Agent》中对Harness工程的定义。

Harness工程包含五个核心功能，缺一不可：

功能 英文 核心职责 一句话理解
上下文与工具 Context & Tools 为LLM提供任务所需的背景信息和行动能力 让Agent能做事
约束 Constraints 限制Agent的行为边界，防止越界操作 让Agent不做不该做的事
验证 Verification 判断Agent的输出和行动结果是否正确 判断结果是否正确
纠正 Correction 出错时恢复到正确状态，避免错误传播 出错时恢复
编排 Orchestration 组织以上四个功能的执行顺序和循环 组织以上功能的循环

五个功能的协作逻辑：编排功能驱动一个主循环，每轮循环中——上下文与工具功能为LLM提供当前所需的信息和行动能力；约束功能确保LLM的输出和行为不越界；验证功能判断本轮结果是否正确；如果验证不通过，纠正功能介入恢复。如此循环，直到任务完成。

2.6.2 Harness与PDA循环的关系

本课前面介绍的PDA循环、六大核心模块，并非与Harness工程并列的另一套体系，而是Harness工程各功能的具体实现：

Harness功能 对应课程内容 实现方式
上下文与工具 记忆系统（模块④）+ 工具集（模块⑤） 记忆系统提供历史上下文，工具集提供行动能力
约束 System Prompt设计 + 工具权限控制 + 终止条件 限制Agent的行为范围和安全边界
验证 评估与监控（模块⑥） 任务完成率、推理质量、工具调用成功率等指标
纠正 反思机制（Reflexion） 行动结果与预期不符时，反思并调整策略
编排 PDA循环（2.2节） 感知→决策→行动→状态更新的循环流程

关键理解：

  • PDA循环是Harness"编排"功能的具体实现——它定义了上下文、工具、验证、纠正四个功能如何按顺序组合运行
  • 记忆系统属于"上下文"功能——为LLM提供任务相关的背景信息
  • 工具体系属于"工具"功能——赋予LLM"行动"能力（Function Calling、MCP）
  • 反思机制属于"纠正"功能——出错时的恢复机制
  • 评估与监控属于"验证"功能——判断结果是否正确

换句话说，本课前面建立的所有架构概念，都可以归入Harness工程的某个功能。这种映射关系不仅适用于本课，后续每课也是如此。

2.6.3 为什么"模型之外的竞争力"越来越重要

进入2026年，一个显著趋势是主流LLM的能力日趋趋同：

当模型本身的能力差距缩小到个位数时，差异化竞争的主战场从"模型层"上移到"Harness工程层"：

竞争维度 2023-2024（模型为王） 2025-2026（Harness为王）
核心壁垒 谁的模型更强 谁的Harness工程更完善
差异化来源 模型参数规模、训练数据 上下文管理、工具编排、约束设计、验证纠错
护城河 模型权重（难以复制） 工程体系（持续迭代积累）
用户感知 “这个AI更聪明” “这个Agent更可靠、更安全、更高效”

对架构设计师的启示：

  1. 不要只盯着"换更强的模型"——模型升级的红利正在递减
  2. 投资Harness工程的五个功能——这才是2026年及以后的竞争力所在
  3. 本课程后续21课，本质上就是在教你如何系统化地构建一个高质量Harness

参考答案

题目1 参考答案

六元组定义：

  • S\mathcal{S}S（状态空间）：Agent的内部状态，包括当前任务、已完成步骤、中间结果
  • A\mathcal{A}A（动作空间）：Agent可执行的动作集合，如调用工具、生成回复、终止任务
  • O\mathcal{O}O（观察空间）：Agent能从环境获取的信息，如工具返回值、用户输入
  • M\mathcal{M}M（记忆系统）：短期记忆（上下文窗口）+ 长期记忆（向量数据库）
  • π\piπ（策略函数）：π:S×M→A\pi: \mathcal{S} \times \mathcal{M} \rightarrow \mathcal{A}π:S×M→A，根据状态和记忆输出动作
  • T\mathcal{T}T（工具集）：Agent可调用的外部工具集合

本质区别：

  • RL Agent的 π\piπ 是通过训练得到的数值函数（神经网络参数），策略是固定的，改变策略需要重新训练
  • LLM Agent的 π\piπ 是由LLM通过自然语言推理实现的，策略可以通过修改Prompt动态调整，无需重训练。LLM Agent能解释自己的决策过程（输出推理链），而RL Agent的决策是黑箱

题目2 参考答案

PDA循环五个步骤：

  1. 感知：获取上一步行动的结果（工具返回值、用户反馈），从记忆系统中检索相关历史信息
  2. 决策：LLM根据当前状态、观察和记忆进行推理，输出下一步动作（Thought → Action）
  3. 行动：执行决策输出的动作（调用工具、生成文本、或终止）
  4. 状态更新：根据行动结果更新Agent内部状态
  5. 记忆更新：将本轮的状态、动作、观察写入记忆系统

反思步骤的触发条件和影响：

  • 触发条件：当行动结果与预期不符时（如工具返回错误、搜索结果为空、中间结果质量低），或达到预设的检查点
  • 影响方式：反思生成对当前策略的评估，写入反思记忆。后续决策步骤会检索反思记忆，调整策略（如更换搜索关键词、选择不同工具、修改任务分解方案）

题目3 参考答案

六大核心模块：①感知模块 ②决策模块（LLM） ③行动模块 ④记忆系统 ⑤工具集 ⑥评估与监控

感知模块解决的问题：将环境中的原始信息（用户输入、工具返回、系统状态）转化为LLM可处理的文本表示。核心挑战是信息压缩（控制Token预算）和格式归一化。在PDA循环中位于"感知"阶段。

评估与监控模块解决的问题：量化Agent的行为质量（任务完成率、推理正确性、工具使用效率、成本效率），追踪每次推理和工具调用的全过程，支持调试和优化。在PDA循环中贯穿全链路——对每个阶段的输入输出进行记录和评估。

题目4 参考答案

维度 (A) MYCIN (B) AlphaGo © LLM Agent
决策核心 人工编写的IF-THEN规则库 训练得到的策略神经网络 LLM的通用自然语言推理
能力扩展方式 添加更多规则（人工编写） 重新训练策略网络 添加工具（通过Function Calling/MCP）
泛化性 无（第601种细菌无法诊断） 无（只能下围棋） 有（可处理开放域任意任务）

LLM是分水岭的原因：

  1. LLM提供了第一个通用推理引擎——无需为每个任务专门训练，零样本即可处理新任务
  2. 能力扩展从"重训练"变为"加工具"——通过标准协议（Function Calling/MCP）连接工具，能力可无限扩展
  3. 知识获取从"编码到参数"变为"运行时检索"——RAG让Agent在运行时获取最新知识
  4. 策略可解释——LLM输出推理链，而RL Agent是黑箱

（c）单Agent升级为多Agent的判断标准：

  1. 上下文窗口不足：单个研究任务的文献信息量超出LLM上下文窗口（如需要同时分析50+篇论文），需要拆分为多个Agent分别处理
  2. 任务并行性：用户同时提交多个独立研究课题，单Agent串行处理延迟过高，需要多Agent并行
  3. 专业能力分化：不同研究阶段需要不同专业能力（如文献检索→统计分析→报告撰写），单Agent难以同时精通，需要专业化分工

（d）记忆类型：

记忆类型 存储信息
短期记忆（工作记忆） 当前研究任务的上下文：已搜索的关键词、已阅读的论文、中间分析结果
Episodic Memory（情景记忆） 过去的研究经历：之前做过什么课题、用了什么方法、得到了什么结论
Semantic Memory（语义记忆） 领域知识：已建立的领域知识图谱、概念关系、常用方法论
Procedural Memory（程序记忆） 研究流程技能：如何高效搜索文献、如何结构化分析论文、如何生成报告的标准模板
反思记忆 过去的经验教训：哪些搜索策略有效、哪些工具组合效率高、哪些错误需要避免
