毕业参考答案：AI Agent系统架构设计（第1-22课全课程）

配套试卷：99-毕业答卷.md
结构：第一部分标准答案 → 第二部分参考方案+评分维度 → 第三部分参考架构方案+评分标准+常见错误模式
使用方式：先独立完成答卷再对照。第二、三部分评分看决策依据的量化程度与全链路完整性——参考方案是”一种好的答案”，不是”唯一的答案”。

第一部分：基础原理（30分，标准答案）

Q1. Attention复杂度与KV Cache容量计算（8分）

（1）公式与复杂度（3分）

$$Attention(Q,K,V) = softmax\left(\frac{QK^T}{\sqrt{d}}\right)V$$

复杂度推导：Q为n×d、K^T为d×n → QK^T为n×n矩阵，计算代价O(n²d)；softmax对n×n矩阵逐行归一化为O(n²)；结果与V（n×d）相乘为O(n²d)。总复杂度O(n²d)——序列长度平方增长是长上下文昂贵的根源（也是RAG存在的根本理由，第10课）。

除以√d的原因：点积 $q \cdot k = \sum_{i=1}^{d} q_i k_i$ 是d个独立项之和，若各分量方差为1，则点积方差为d、标准差为√d。d=128时点积量级11，softmax进入饱和区→梯度消失。除以√d将logit方差拉回1，保持softmax在敏感区（训练稳定性的关键）。

（2）KV Cache计算（3分）

每token KV = 2（K与V）× 层数 × KV头数 × head_dim × 精度字节

= 2 × 32 × 8 × 128 × 2 B = 131,072 B = 128 KB/token

单请求16,384 token：128 KB × 16,384 = 2,097,152 KB = 2 GB

（3）并发上限与GQA（2分）

可用显存 = 48 × 0.90 = 43.2 GB；固定开销 = 4 × 0.12 = 0.48 GB
KV可用 = 43.2 − 4 − 0.48 = 38.72 GB
理论并发上限 = 38.72 / 2 ≈ 19路在途请求

GQA的量化影响：若无GQA（32个KV头），每token KV = 2×32×32×128×2 = 512 KB，单请求KV = 8 GB，并发上限仅~4路。GQA把KV头从32降到8，并发容量提升4倍——这是推理服务吞吐的第一杠杆（第2课）。

Q2. 检索数学：InfoNCE与RRF（8分）

（1）InfoNCE（3分）

$$\mathcal{L}{InfoNCE} = -\log \frac{\exp(s(q, d^+)/\tau)}{\exp(s(q,d^+)/\tau) + \sum{j=1}^{N} \exp(s(q, d_j^-)/\tau)}$$

其中s为相似度函数（如余弦或点积），τ为温度，d⁺为正样本，d⁻为批内负样本。

塑造几何结构的机制：最小化该损失等价于最大化正样本的后验概率——分子拉进query与正文档的相似度，分母（softmax的分母构成”锦标赛”）推远query与负文档。数百万”query-正文档-负文档”三元组训练后，语义相似度被系统地编码为向量空间邻近度。温度τ控制负样本的”难度”：τ小→只有最难的负样本主导梯度。所以”相似语义在向量空间邻近”不是先验属性，是对比目标的解（第6课）。

（2）RRF计算（3分）

score(d) = Σ_r 1/(k + rank_r(d))，k=60：

  • A：1/61 + 1/64 = 0.01639 + 0.01563 = 0.03202
  • B：1/62 + 1/62 = 0.01613 + 0.01613 = 0.03226
  • C：1/61 + 1/90 = 0.01639 + 0.01111 = 0.02750
  • D：1/65 + 1/61 = 0.01538 + 0.01639 = 0.03178

排序：B > A > D > C

核心哲学：B两路都只排第2却总分第一——共识文档胜出；C在BM25排第1（术语精确匹配强）但稠密排第30，被显著打折——RRF抑制单路偏见，单路极端靠前的文档无法仅凭一路登顶。这正是混合检索的设计意图：BM25与稠密向量的错误模式不同（术语vs语义），共识信号比单点信号可信（第7课）。

（3）量纲免疫（2分）

RRF只消费排名（序数），完全不消费原始分数——BM25无上界、余弦[-1,1]、点积无界这些量纲差异在输入端就被排名化消除了。相比加权融合：①无需分数归一化（min-max/z-score在分布漂移下脆弱——BM25分数分布随语料变化）；②无需按query类型调融合权重（加权法需要”术语型query加大BM25权重”之类的调参）；③唯一超参k=60是社区标准值，鲁棒。代价是丢弃了分数中的置信信息（两路都第1但一个自信一个勉强，RRF无法区分）——工程上这笔交换几乎总是划算。

Q3. 持续进化的数学（7分）

（1）灰度样本量（3分）

$$n \approx \frac{16\sigma^2}{\Delta^2} = \frac{16 \times 0.10^2}{0.02^2} = \frac{16 \times 0.01}{0.0004} = 400$$

每档需400个样本才能在80%功效下检测2个百分点的提升。

“16”的来源：双样本检验的样本量 $n = 2(z_{\alpha/2}+z_\beta)^2\sigma^2/\Delta^2$。α=0.05双侧→z=1.96；功效80%→z_β=0.84；(1.96+0.84)² = 7.84；×2 ≈ 15.7 ≈ 16。记忆法：16 = 2 × (2.8)²，2.8 = 1.96 + 0.84（第21课）。

（2）载体路由（2分）

badcase 归因 载体 ROI形式化理由
b1 工具调用幻觉 能力不足 模型参数（SFT微调） ROI = 100×0.95 − SFT成本 − 验证成本 − 回归风险×回滚成本。硬信号+高置信+重复9次（轻载体已试过并失败——重复出现即升级信号）→ 只有改参数才能根治能力缺陷
b2 引用格式偶发 行为偏差 Prompt/Skills（先提升置信） 软信号单次置信0.6 → 先入观察池，做3次独立多数投票（q=0.7时3次多数≈0.78）再决策；行为规范写入系统提示词的成本几乎为0，ROI = 20×0.78 − ε
b3 新方法综述缺失 知识缺失 知识文档（直接做） ROI = 30×0.9 − 极低（一篇文档）− 极低 − 点状影响×秒级回滚 → 最高优先级。知识缺失是最轻载体可解的（第21课）

（3）守护指标 vs 学习指标（2分）

守护指标：既有能力不回退（Golden Dataset分数、P99延迟、工具成功率、拒答率、Token成本）；学习指标：目标能力提升（badcase修复率）。灰度期间优先证明无害的原因：不对称性——一次回归造成的用户信任损失与数据污染（记忆/知识库被写坏可能不可逆）远大于一次提升的收益；且学习指标本身有统计噪声（n不足时”提升”可能是幻觉），守护指标回退是更明确的信号。”先证明无害，再证明有益”。

Q4. 概念辨析（7分）

（1）Harness vs Agent（约2分）

Agent = 模型 + Harness + 工具构成的完整自主执行体；Harness只是管理Agent如何运行的软件系统——上下文与工具、约束、验证、纠正、编排五功能。Agent是”马”，Harness是”马鞍与缰绳”。第1课例：PDA循环是Harness编排功能的具体实现，模型换了Harness不变；第22课例：Claude Code里/skill-doctor管理上下文成本（上下文功能）、审查状态机拦截非法转移（约束功能）、”Plan是合同”的门禁（编排功能）——AI编程产品就是Harness工程的产品化。架构含义：能力跟随模型换代，你的架构资产沉淀在Harness层。

（2）Agentic RAG vs 预检索RAG（约2分）

本质区别是检索决策权从固定流水线逻辑转移到Agent（模型）：预检索RAG每次查询无条件检索一次、固定拼接；Agentic RAG由Agent自主决定何时检索（Self-RAG反思token判定）、检索什么（query改写/多路分解）、检索几次（CRAG三级纠正、多跳）、是否使用结果。新能力：多跳聚合、动态路由、自纠正、置信校准。新风险：延迟不可预测（循环次数不定）、Token成本膨胀（每轮重放上下文）、错误传播（检索决策错误污染下游）、评估复杂化（从结果级评估升级为轨迹级评估）。

（3）MCP vs A2A（约1.5分）

MCP解决Agent与工具/能力的接入：client-server模式，Agent作为消费者调用工具服务器（文献检索、计算、沙箱）——“Agent怎么用工具”。A2A解决Agent与Agent的对等协作：peer模式，Task生命周期管理（八状态机）、Agent Card能力发现与签名信任——“Agent怎么找Agent并委托任务”。定位差异：把文献检索做成MCP Server是发布能力（垂直整合，一次实现多方复用）；A2A调用统计Agent是委托任务（水平协作，跨黑盒协作但保留各自内部架构）。研究助手两者都要：MCP向内管理工具生态，A2A向外组织协作。

（4）时间维调度 vs 空间维协作（约1.5分）

OpenManus的单一ReAct循环（含PlanningFlow）是时间维调度：一个Agent在不同时刻依次执行不同步骤，全程共享一个上下文与一个工具集——没有”多个独立决策主体同时存在”。真多Agent判据是空间维协作：多个Agent同时在场、各自有独立上下文窗口与工具子集、通过消息传递或共享工件协作、存在任务分配与结果聚合。判据的工程意义：只有空间维协作才产生协调复杂度（死锁、对齐失败、MAST研究揭示的41%-87%生产失败率——协调缺陷而非模型能力是主因）。时间维调度不需要多Agent通信协议、死锁检测这些重装备——用对架构的第一步是判断你到底需不需要它们。

第二部分：技术选型（30分，参考方案+评分维度）

通用评分：6维度各1-5分。5分=量化决策+被否决方案有数据支撑+风险预案；3分=方向正确但缺量化；1分=罗列名词无决策依据。

Q5. 模型定制与压缩组合选型（10分）——参考方案

① Worker更新路径：QLoRA SFT（不是RL，不是纯Prompt，不是OPD）

  • 数据工程（本题关键得分点）：”修正对”直接SFT存在分布偏移——训练集全是hard cases（模型犯错→被修正），模型会学到”过度修正”行为（对本来正确的调用也犹豫）。筛选方法：a) 按错误类型分层采样，使训练分布匹配真实错误率；b) 混入正常轨迹（约1:3错误:正常比例），保持行为先验；c) 去重与来源校验；d) 留出15%做验证集（评估工具调用格式准确率）。
  • 否决RL：无RL经验+$2,000+48小时窗口——GRPO需要rollout基础设施、奖励设计、轨迹缓存（CacheRL）三样重装备，风险与预算双否决（第17课选型矩阵：”团队没有的能力比缺钱更贵”）。
  • 否决纯Prompt：badcase是能力不足型（参数幻觉），第21课已论证能力缺陷是轻载体的边界——重复出现的错误就是轻载体失败的证据。
  • 否决OPD：OPD适合传递复杂推理策略且需教师在线交互；修正对是静态离线数据，标准SFT足够。
  • 实施顺序：数据清洗与分层采样 → QLoRA（r=16，NF4）在2×A100上微调7B约12-24小时 → 评估集验证（工具调用格式准确率基线对比）→ 回归检测 → 灰度发布。

② 主模型32B压缩：AWQ-Int4

  • 权重FP16 64GB → AWQ-Int4约18GB（缩小3.5倍）；依据：AWQ为服务端新量化默认——PPL损失3.4%四格式最优、推理吞吐比FP16快31%（第18课实证）；18GB可单卡H100 80GB部署，余量62GB全给KV。
  • 否决FP8：需Hopper+（sm_89），若部署节点是A100则不可用；且32GB仍是Int4的1.7倍（FP8适合H100/H200上的极致延迟场景，本题成本优先）。
  • 否决GPTQ：定位是复用社区已有artifact省量化成本；全新量化首选AWQ。
  • 否决GGUF：CPU/Apple Silicon/端侧格式，服务器高并发场景（Continuous Batching+高带宽需求）不适用。
  • 吞吐估算依据：decode阶段带宽受限，权重读取量减少3.5倍 → 内存带宽压力同比例下降，batch内吞吐提升约30%（与社区实测一致）。

③ 粗筛0.5B→1.5B：量化置换，零GPU增量

关键洞察：0.5B FP16权重≈1GB，1.5B AWQ-Int4权重≈0.9GB——量化让升级几乎不增加显存。直接在同一张卡上原位替换；吞吐损失（1.5B算力约0.5B的1/3）由Embedding负载的批处理特性吸收（粗筛是吞吐型而非延迟型任务），必要时启用ONNX Runtime导出与INT8推理补偿。若仍不达标，与Reranker共卡（0.9+0.6GB，48GB卡绰绰有余）。

Q6. 知识架构选型（10分）——参考方案

① 分块与混合检索

  • 分块：论文结构化感知分块（标题/段落/图表caption为边界）+ 父子分块（细粒度子块检索命中、粗粒度父块喂给生成——检索精度与上下文完整性的解耦）；图表走多模态抽取（VLM提取入库，第10课）。
  • 检索：BM25（术语/缩写/作者名精确匹配）+ BGE-M3稠密（语义）双路，RRF融合（k=60）；粗筛TOP-100+TOP-100 → RRF → 重排序BGE-Reranker-v2-m3（568M，多语言默认）→ TOP-10。
  • 成本核算：Embedding服务批处理，50万库的一次向量检索在HNSW上毫秒级；单查询$0.05预算主要被LLM生成消耗，检索链路（Embedding+重排序GPU）分摊后<$0.005——预算重点在控制生成端（prompt缓存+答案长度约束）。

② GraphRAG：引入但只路由给多跳聚合

  • 路由设计（查询分类器前置）：简单事实型（”X方法的召回率是多少”）→ BM25+稠密直检（WildGraphBench实证：简单事实查询BM25仍有竞争力且成本低一个量级）；多跳聚合型（”近两年该领域方法演进脉络”）→ GraphRAG Global模式（社区级摘要聚合）或DRIFT式局部遍历（低成本多跳）；混合型 → 先直检定位锚点文献，再图遍历扩展。
  • 成本控制：GraphRAG索引贵（实体抽取是LLM调用）——只对高影响力子集建图（TOP-1000高被引论文），其余纯向量；采用LightRAG式增量图更新（v1.5.x主打工程落地）。

③ 增量索引：全量重建不可行

15亿token全量重建=全库重新Embedding（GPU小时级成本）+索引不可用窗口——每日执行不可行。方案：HNSW动态插入+BM25倒排索引天然增量+新增文献异步流水线（RSS抓取→解析→分块→Embedding→双索引写入，30分钟一批），2小时SLA留足余量；删除/更新用软删除标记+周期压实。

④ Agentic RAG决策树

Q7. 编排框架与互操作选型（10分）——参考方案

① 框架：LangGraph自研编排 + 协议适配层

  • 决策原则（第22课）：”框架是易变层，协议是稳定层”——AutoGen进维护模式、MAF接棒的2026年案例证明框架更替是常态；把业务逻辑挂在MCP/A2A协议抽象上，框架做成可替换实现。
  • 具体架构：工具调用统一走自建MCP client适配层（协议接口不变），编排层与LangGraph之间加一层薄抽象（图定义DSL）——未来切换MAF只重写适配层。
  • 否决MAF：AutoGen+SK合并的继任者（YAML声明+原生MCP/A2A，适合新项目快速起步），但迁移成本高+微软生态绑定，且团队已深耕LangGraph（第12课：checkpoint/HITL/CVE修复经验都是资产）。
  • 否决OpenManus二次开发：优秀的参考实现（四层架构值得学习）但非生产底座——沙箱默认弱隔离（批判性案例）、社区驱动节奏不可控、单ReAct循环天花板。
  • 迁移策略：新功能以协议为先（先写MCP Server再加编排），存量LangGraph图保持运行。

② MCP Server化：收益与安全边界

  • 收益：能力复用（其他部门Agent直接消费）、解耦（研究助手自己也调用同一Server——单一事实源）、v2.0无状态架构原生适配Serverless弹性部署。
  • 安全边界（本题主要得分点）：a) 只读接口（检索/摘要对外，写入操作仅限内部）；b) 租户隔离（每调用方独立quota与数据视图）；c) 审计日志（谁、何时、查了什么——合规180天留存要求的服务端落实）；d) 限流与header路由（网关层Mcp-Method头路由，免解析body即可限流，v2.0特性）；e) 版权分层：内部调用返回全文片段，外部Agent只返回摘要+引用。

③ A2A接入统计Agent：立即接入，保留降级

  • 取舍：自研统计模块（开发+维护+验证成本）vs A2A接入（协议适配+信任建立成本）——专业统计能力差异大且调用高频，接入划算。
  • 信任建立：Signed Agent Card（JWS签名+RFC 8785规范化，防能力欺骗：公开URL上的Card防篡改）+ 执行验证（能力协商的”可验证博弈”）。
  • 风险管理：外部Agent当工具用——超时控制、结果验证（抽样复核）、数据最小化（只传匿名化中间结果，不传用户原始query，满足合规审计）。
  • 降级路径：A2A服务不可用→本地基础统计工具兜底（能力降级不服务中断）。

④ 代码分析模块：分层决策（第22课收官之问）

  • 默认不内建：能力半径膨胀+低频需求+每个工具都是攻击面（OWASP rogue agent路径）+四载体ROI框架下低频需求ROI为负。
  • 执行态MCP外挂：独立代码分析工具服务器（repo_overview / code_search / method_digest三工具），只读挂载+网络白名单+30s超时+输出截断，按需启用。
  • 报告态元信息：检索结果关联GitHub仓库元数据（star/语言/活跃度），零工具链成本覆盖80%需求。
  • 决策本质：能力边界是刻意的架构选择而非能力不足——这也是毕业答卷第9部分”治理与能力边界”的预演。

第三部分：系统设计（40分，参考架构方案+评分标准+常见错误模式）

Q8. 参考架构方案：企业级智能研究助手Agent系统

3.1 整体架构图

Harness五功能落点：①约束（接入层WAF+工具分级+状态机门禁）②上下文与工具（Skills按需加载+MCP工具集群）③验证（工具输出即证据+评估体系）④纠正（checkpoint恢复+FIXING循环+回滚）⑤编排（LangGraph图+事件总线+灰度调度）。

3.2 模型栈设计

模型 选型 形态 定制路径 显存核算
Planner Qwen3-32B FP8（2×H100 TP2） 不微调：prompt工程+结构化输出约束；18个月后视badcase决定 权重32GB；KV可用≈108GB→54路在途（16k上下文FP8 KV 2GB/路）；Planner流量占比~30%（30路）→单副本充足
Worker Qwen3-7B AWQ-Int4（4×L40S独立部署） QLoRA SFT：进化闭环积累的修正对（分层采样+混入正常轨迹1:3）→ 工具调用格式与选择策略 每卡权重4GB+开销→KV可用39GB→39路/卡×4=156路 ✓
粗筛 Qwen3-Embedding-1.5B + BGE-Reranker-v2-m3 AWQ-Int4/FP16（1×L40S共卡） 不微调（检索模型选型优于定制） 合计<2GB，与峰值CPU推理降级互备

选型理由：三模型分工对应第20课Planner-Worker模式（强模型决策+轻模型执行，第22课第三次出现的同一架构模式）；FP8选在H100上是吞吐甜点位（NVIDIA官方建议Hopper用FP8）；7B用AWQ是服务端Int4默认。

3.3 推理服务与集群

  • 三约束容量计算（取最大）：①显存：如上，Worker 156路>100路在途需求 ✓，Planner 54路>30路需求 ✓；②解码带宽：7B AWQ 4GB权重，L40S 864GB/s→单token权重读取4.6ms，batch=16摊销→每卡吞吐210 tok/s，4卡840 tok/s，100路×平均8 tok/s需求 ✓；③Prefill算力：16k prompt在L40S上~1.5s，TTFT P99<2.5s需prefix caching配合（见下）。
  • prefix caching：系统提示词+工具描述+Skills头是固定前缀（4k token），命中率>60%时TTFT从1.5s降至~0.5s——这是TTFT达标的第一杠杆。
  • 弹性伸缩：KEDA以vllm:num_requests_waiting（队列深度）为信号（HPA基于GPU利用率失效——生产均值~5%）；cooldown 180s防抖动；Worker四卡天然分散。
  • 冷启动：Planner副本用Sleep Mode守护实例（唤醒~5s，对比权重冷启动521s的实证教训）+权重预放置+编译缓存复用；Spot中断预案（H100 p5中断<5%、警告2min→主动drain流量）。
  • 可用性99.9%：Planner单副本风险→Spot基线+OD兜底（月预算允许峰值临时扩容第二副本）；Worker/MCP/DB多副本；全链路降级路径（vLLM不可用→API模型兜底；GraphRAG不可用→直检降级）。

3.4 协作与互操作

  • 多Agent判断（第14课五问过一遍）：核心链路是Orchestrator-Worker（Planner编排+Worker执行+共享黑板状态）——这是”空间上分离、控制上集中”的分层模式而非对等Swarm；不做全对等多Agent（MAST教训：41%-87%生产失败率，最大根因是系统设计缺陷/协调缺陷——研究助手主链路求稳，协作用在刀刃上）。
  • 并行化：多文献并行检索/多源并行验证（Anthropic经验：并行子Agent90%墙钟缩减，代价15倍token开销——只并行独立子任务，摘要聚合回主链路）。
  • MCP：全部工具MCP Server化（v2.0无状态→Serverless弹性）；网关header路由+限流+审计。
  • A2A：接入外部统计Agent（Signed Agent Card+执行验证+数据最小化）；对外暴露综述能力（Task八状态机、多租户）。

3.5 知识增强

  • 分块：结构化语义分块+父子分块；多模态图表VLM入库。
  • 检索：BM25+BGE-M3双路RRF→重排TOP-10；GraphRAG高影响力子集（多跳聚合路由）；增量索引流水线（30分钟批，2小时SLA）。
  • 记忆三层：短期（LangGraph state+滑动窗口+摘要压缩，Token预算显式分配）；长期（Milvus向量+PostgreSQL结构化：用户偏好/项目上下文/引用格式习惯，valid_from/valid_to版本化）；组织知识（最佳检索策略与领域术语Skills化，SKILL.md+索引按需加载）。
  • 记忆写入走进化闭环（白名单+检索消毒+审计台账——记忆污染防御，第9课）。

3.6 安全设计（四层）

  1. 输入层：WAF注入检测（指令/数据分离模板）、输入消毒、内容分级。
  2. 工具层：危险操作三级分级（只读/写/不可逆——写需确认，不可逆需双人复核）；超时控制（每工具30s默认）；沙箱只读挂载+网络白名单；全链路审计日志。
  3. 部署层：vLLM与工具服务器VPC分段隔离；凭据带外（K8s Secrets，不进prompt）；checkpoint安全（LangGraph≥1.2.5修复CVE-2025-64439反序列化RCE——“checkpoint即攻击面”）；日志脱敏留存180天（合规）。
  4. 跨组织层：A2A Signed Agent Card（JWS+RFC 8785规范化）+OAuth2 Device Flow/PKCE；租户隔离；数据最小化。

3.7 评估与可观测

  • 离线评估：Golden Dataset 500题（事实/聚合/观点三型分层）+LLM-as-a-Judge双Judge交叉+顺序交换（单Judge与ground truth一致率仅87.6%、位置偏差0.73——生产纪律）+每次发布跑回归检测。
  • 在线监控：TTFT/E2E P99、Token成本/查询、检索命中率、引用准确率（5%抽样人审）、工具调用成功率、拒答率。
  • 告警与自愈闭环：P99>3s持续5min→KEDA扩容；错误率>2%→自动回滚；成本>日预算80%→告警+路由降级。所有线上badcase自动进入进化层学习信号管道——评估不是终点的打分，是进化的燃料（第10课评估闭环+第21课）。

3.8 持续进化机制（第21课——毕业核心增量一）

  • 信号采集：工具调用失败/超时（硬信号，自动捕获）；引用格式/规范violation（半硬规则信号）；Rubric综述质量评审（软信号，3次多数投票提升置信：q=0.7→0.784）。
  • 置信分流：高置信→处理流；低置信→观察池（累计升级）。
  • 载体路由：归因→载体映射（流程缺陷→程序/行为偏差→Prompt/知识缺失→知识文档/能力不足→模型参数）+ROI=收益×置信−更新−验证−回归×回滚，逐案计算排序。
  • 三道闸门：评估集验证+回归检测+高风险人工终审。
  • 灰度：1%→5%→25%→100%，每档n≈16σ²/Δ²（指标σ=0.1、Δ=0.02时400样本/档）；守护指标集={Golden分数、P99延迟、工具成功率、拒答率、Token成本}任一回退→自动回滚。
  • 长期知识整理：季度性记忆巩固（episodic→semantic提升）+冲突解决（时间戳版本化，被反驳不删除）。

3.9 治理与能力边界（第22课——毕业核心增量二）

  • 审查闭环状态机：知识库/记忆/Skills的所有写入走 PROPOSING→HARD-GATE（待澄清清零+显式确认）→APPLYING→REVIEW_SPEC（”不信报告只信代码”式核验）→REVIEW_QUALITY（分级）→ARCHIVED（知识沉淀）；FIXING循环带文档同步铁律。HARD-GATE必须是状态机里到不了的转移边（结构性约束），不是提示词里的”请勿”。
  • 团队三角色：Spec架构师（维护Golden Dataset与验收标准=L3人审重心）；AI训练师（rules/knowledge/Skills飞轮管理=进化闭环运营者）；质量验证师（Eval Harness+CI门禁+双Judge治理）。
  • 自举安全边界：L1知识文档（全自动，秒级回滚）✓；L2 Prompt/Skills（Agent起草、人批准）✓；L3程序/Harness（人工代码审查+分支合并）✓；L4模型参数（只走离线训练管道，Agent不在线自改）；L5能力核心✗。宪法核心保护：评估体系本身（Golden Dataset+守护指标+回滚机制+审查状态机）对Agent只读——进化不能修改自己的裁判，否则护栏在进化压力下失去权威性（Ouroboros案例的核心教训）。

3.10 成本估算与演进路线

项目 配置 月成本

Worker推理 4×L40S ~$2,850
Embedding+重排 1×L40S（与CPU降级互备） ~$710

Token成本控制：prefix caching（省~60%系统前缀）、粗筛路由（70%简单查询不进Planner全流程）、语义缓存（重复查询命中）、答案长度分级。

18个月演进路线：

  • M0-3 MVP：100用户/50并发；单副本+基础RAG（BM25+稠密）；Golden Dataset 100题跑通评估闭环；进化信号管道V1（只采集不发布）。
  • M4-9 生产化：500并发；K8s+KEDA+MCP Server化+安全四层完备；A2A统计Agent接入；进化闭环上线（灰度+回滚全链路）；Worker QLoRA SFT v1。
  • M10-18 规模化+进化：2000用户；GraphRAG高影响力子集；Worker SFT v2（12k+修正对全量）；对外MCP服务开放（配额制）；Agentic RL试点（若badcase显示SFT天花板——奖励信号已由进化闭环积累）；多模态深度（图表理解VLM升级）。

评分标准（第三部分，6维度各1-5分+架构图10分）

维度 5分 3分 1分
①技术选型合理性 三约束算出数字，选型与预算/并发/SLO逐一对应，被否决方案有量化对比 方向正确（vLLM/AWQ/MCP等主流选型）但无容量计算 罗列技术名词无决策依据

架构图完整性与整体连贯性（10分）：分层清晰5分；五功能/双线（知识+项目）标注与正文对应5分。

常见错误模式（自评后重点检查）

典型架构设计错误：

  1. 无进化机制——上线即巅峰，三个月后退化（知识过期、行为漂移无回流）；这是毕业答卷相对E020的核心增量，缺失即失去”时间维度”分数
  2. 评估体系可被Agent修改——进化失去裁判，护栏在自举压力下失效（宪法核心必须只读）
  3. 记忆无版本化——污染后无法回滚，长期记忆被坏数据永久损坏
  4. 单点无降级路径——vLLM或GraphRAG不可用时全站不可用，99.9%无从谈起
  5. 无统计显著性意识——n=50就宣称灰度”提升”，实际是噪声（n≈16σ²/Δ²）
  6. HARD-GATE写成提示词——“请不要直接发布”是劝阻不是约束；约束必须结构性不可达（状态机拦截）

典型选型错误：

  1. 高并发场景选不支持Continuous Batching的推理引擎（静态批的队头阻塞）
  2. 32B模型FP16部署（成本约4倍于Int4/2倍于FP8）
  3. 简单事实查询也全走GraphRAG（BM25便宜一个量级且简单查询不输——WildGraphBench实证）
  4. 堆全对等多Agent（MAST：41%-87%生产失败率，主因协调缺陷而非模型能力）
  5. 无RL经验与预算却选Agentic RL路径（SFT先行的次序不可颠倒——“SFT记忆格式，RL泛化策略”）
  6. 服务器场景选GGUF格式（端侧格式，高并发不适用）
  7. 忽略prefix caching（研究助手固定系统前缀，命中率>60%，TTFT第一杠杆）

典型安全遗漏：

  1. 未设计Prompt注入防御（研究助手消费外部文献——文献内容是不可信输入，注入向量天然存在）
  2. 工具调用无超时控制（一个工具挂死阻塞整个ReAct循环）
  3. 沙箱默认弱隔离（OpenManus PythonExecute批判：safe_globals仍暴露完整builtins；正确做法Docker+network_mode=none或只读挂载）
  4. checkpoint反序列化暴露（LangGraph CVE-2025-64439 RCE——checkpoint即攻击面，必须≥1.2.5）
  5. MCP对外服务无租户隔离与审计（跨部门数据调用不可审计，违反合规要求）
  6. 灰度无守护指标（回归不可见——只看学习指标等于蒙眼发布）
  7. 凭据进prompt（必须带外：K8s Secrets/环境注入）
