二、本课对”企业级智能研究助手Agent系统”的贡献

第20课结束时，研究助手有了完整的”物理实现”：1000并发的三池集群、Planner-Worker混部、KEDA弹性伸缩。但那是一套”冻结在今天”的架构。本课回答的是部署之后的架构师问题：系统上线三个月后开始变差，你怎么办？

本课产出四个项目资产，它们合起来构成毕业答卷的”系统持续演进”章节：

  1. 学习信号管道——三类信号的采集、质量评估与置信分流（§4）
  2. 载体路由决策规则——四载体ROI矩阵与归因→载体的映射（§5）
  3. 灰度发布与回滚方案——三道闸门、阶梯设计、守护指标、回滚预案（§6）
  4. 进化闭环全景图——从badcase到全量发布/回滚的完整机制（§6.4、§10）

第20课留下的钩子今天兑现：badcase不再只进评估集（第10课），而要回流到”正确的更新载体”——这句话是本课的全部主线。

三、开篇：上线第一天，系统开始退化（3min）

研究助手上线三个月后，你收到了三类坏消息：

  1. 环境漂移：arXiv改版导致检索工具频繁返回403；某文献数据库的API限流策略收紧，工具调用超时率从0.3%涨到2.1%——环境在变，你的代码没变
  2. 知识过时：用户问”XX领域2026年的最新方法”，知识库里最新的综述停在了上年——世界在产生新知识，你的知识库没长
  3. 模型漂移：供应商模型按月度快照更新（第19课已讲：模型快照约每月发布一次，安全后训练在点版本间并非无害），某次升级后工具调用的JSON格式错误率悄悄上升——基座在换，你的适配没跟

结论：不进化的Agent系统，质量单调递减。第20课给你的是静态最优；本课给你的是动态最优——把”系统随时间变强”设计成一项系统能力。

本课的组织逻辑是三个问题：

  • 学什么——学习信号从哪里来，哪些可信（§4）
  • 存哪里——学到的东西放进四种载体的哪一个（§5）
  • 怎么上线——怎么验证、怎么灰度、怎么回滚（§6）

四、学习信号：系统从哪里学习（必须掌握，7min）

4.1 三个badcase，三种”谁发现的”

badcase 症状 谁发现的 信号类型
B-073 arXiv检索403拒绝，任务中断 系统自己（工具抛异常） 环境执行结果
B-081 综述输出引用格式不符合schema 校验器（第10课输出校验） 过程规则
B-090 用户反馈”综述写得没重点” LLM-as-a-Judge评分3.2/5 LLM Rubric

三种来源对应三类学习信号。学习信号的定义：一条可用于归因系统缺陷的证据三元组 s = (症状, 证据, 归因)——症状是可观察的失败表现，证据是支撑判断的原始数据，归因是”缺陷在哪一层”的判断（知识？行为？流程？能力？）。

4.2 三类学习信号的信噪特性（必须掌握）

类型1：环境执行结果（硬信号）

  • 内容：工具执行返回码、异常堆栈、超时、重试成功与否、网络错误
  • 例子：B-073的403；某次调用DeepSeek API返回429
  • 特性：归因准确率接近1（错误码是确定性的）——但覆盖面窄：它只告诉你”这一步没成功”，不告诉你”该怎么改”
  • 采集：第19课的可观测性体系已经在采（metrics里的工具错误率、trace里的异常标记）——硬信号是免费的，问题在于没人把它接进进化管道

类型2：过程规则（半硬信号）

  • 内容：确定性检查器的输出——schema校验、引用可解析性、JSON结构合法性、格式规范
  • 例子：B-081的引用schema失败；”输出必须包含Sources节”规则触发
  • 特性：准确且可解释（规则触发点即缺陷位置的证据）；局限：规则集需要人工预先定义——而规则集本身也是会过时的（这就是为什么规则集也要版本化、也要进进化闭环）
  • 采集：第10课的评估流水线（RAGAS+规则检查）在线上跑的版本

类型3：LLM Rubric（软信号）

  • 内容：LLM-as-a-Judge按评分量表（rubric）对输出质量打分，低分输出即badcase候选
  • 例子：B-090的”3.2/5分”；双Judge交叉判定综述质量不达标
  • 特性：覆盖面最广（能评”好不好”这种主观维度——硬信号和规则都够不着），但噪声最大：第10课讲过的五大偏差（位置偏差/自我偏好/冗长偏差/评分随机性/显著性不足）全部适用于judge本身
  • 采集：对采样流量（如5%）跑Judge，或对用户点踩的case跑Judge复核

补充：用户行为信号（隐式：重试、放弃、改写重问；显式：点赞点踩）——噪声最大的信号源，单独使用时只做参考不做归因，通常作为”触发Rubric复评”的扳机而不是直接进化的依据。

三类信号对比表：

维度 环境执行结果 过程规则 LLM Rubric
归因准确率 ~1.0（确定性） 高（取决于规则质量） 低（~0.7，有偏差）

工程结论（信号金字塔）：底座是免费的硬信号（全部自动回流），中间是规则（自动回流+规则集版本化），顶层是软信号（必须过置信度门槛）。信号的价值不在多，而在可归因。

五、更新载体：学到的东西放到哪里（必须掌握，6min）

5.1 同一个badcase的四种”存法”

对”知识库缺少2026年新方法综述”（B-090背后的归因之一），你有四种修复位置：

  1. 知识文档：往RAG库里加一篇新综述文档（第6-8课的向量库+分块+索引）
  2. Prompt与Skills：改系统提示词”综述优先检索近两年文献”，或写一个SKILL.md（第4课）定义”文献时效性检查”技能
  3. 程序与Harness：写代码实现”检索时自动附加时间过滤器+近因加权”的逻辑
  4. 模型参数：微调模型让它”天生”知道检索要限定时间（第17课SFT/RL）

四种载体改变的是系统的不同层：事实层（知道什么）、行为层（怎么做事）、能力层（能做什么）、直觉层（权重里的先验）。

Agent Skills现状【联网更新v6.6】：Prompt与Skills这个载体已经标准化——Anthropic于2025-10推出Agent Skills，2025-12-18在agentskills.io以开放标准发布，2026-06已有约40个兼容产品（OpenAI Codex、GitHub Copilot、Cursor、Gemini CLI、VS Code）。核心机制：SKILL.md（YAML元数据name/description预加载+正文按需加载，正是第4课讲过的渐进式上下文披露）。生态治理数据值得架构师记住：第三方分析47150个公开skills的平均质量分仅6.2/12，但精选skills能使Agent通过率平均提升16.2个百分点；安全审计发现36%的skills存在提示注入——引入外部skill必须过三件套：来源审计、最小权限、SKILL.md内容审查。

5.3 ROI形式化与决策顺序（本课数学核心之二）

载体ROI公式：

默认决策顺序（从便宜到贵）：知识 → Prompt/Skills → 程序 → 参数。三问判断法：

  1. 能用知识解决吗？——缺陷是”事实缺失”（新方法、新政策、领域更新）→ 知识文档
  2. 能用指令解决吗？——缺陷是”行为不对”（忽略用户限定、格式不合规）→ Prompt/Skills
  3. 必须动代码或参数吗？——缺陷是”流程缺陷”（缺重试、缺降级）或”能力不足”（幻觉参数）→ 程序/Harness优先，参数最后

判断”该进参数”的三个信号（同时满足才考虑）：

  1. 同类错误跨query稳定复现——是分布性问题而不是个案
  2. 便宜的载体已经试过或塞不下——prompt已经很长、知识已覆盖仍然错
  3. 该判断需要内化到低延迟路径——每次推理都要的能力，检索和指令兜不住

理论背书【联网更新v6.6】：2026-07综述（arXiv:2607.13104）把Agent自改进形式化为”基础模型改进（微调/奖励学习）+脚手架改进（提示/工具/代码/工作流）”两大类——本课的载体排序正是这个框架的工程化：脚手架改进便宜、快、可逆，运营时随时做；基础模型改进贵、慢、全局，离线批量做。第17课CacheRL的实证结论”数据质量与奖励设计比复杂优化算法更重要”在这里同样成立：大部分badcase是知识和流程问题，不是参数问题——先修便宜的载体，参数是最后手段。

5.4 长期知识整理（防腐化）

更新载体不是只进不出的仓库。知识库的三种腐化：

腐化类型 症状 整理机制
过期（stale） 旧方法综述与新事实矛盾 时效字段+定期复核；引用计数低于阈值的候选淘汰
重复（redundancy） 三篇内容相近的文档互相稀释检索权重 相似度聚类去重+合并（保留信息密度最高的一篇）
冲突（contradiction） 同一问题两个版本答案 时序仲裁（新覆盖旧）+人工裁决标记

与第9课的连接：第9课的三因子评分与指数遗忘曲线本是”个体记忆”的检索机制；长期知识整理是把它升级到”组织知识”层——个体记忆解决”这个用户这次会话需要什么”，组织知识解决”系统长期相信什么”。定期把高频调用、高命中率的记忆/文档”蒸馏”为规范知识条目，是记忆系统向知识库的反向沉淀。

六、验证、灰度发布与回滚（必须掌握，4min）

6.1 三道闸门

任何载体的变更（哪怕只是加一篇文档）都要过三道闸门：

  • 离线回归：第10课的评估集（golden dataset+LLM-as-a-Judge）就是为此准备的——变更前后各跑一遍，红线指标不回退才放行
  • 影子运行：新版本接收生产流量副本，输出不返回用户——零风险地观察真实分布下的行为差异
  • 灰度：真实流量小比例切换——本课的重点

阶梯 日样本量 停留天数（=6400/日样本）

结论（架构师的耐心经济学）：灰度的耐心主要花在低流量阶段——完整走完阶梯要11天。跳过1%直接上5%省7天，但等于放弃检测小概率回归的能力；反过来，每档都停满周期会拖慢所有迭代。这是决策不是教条：变更风险越低（知识文档）阶梯越短，风险越高（模型参数）阶梯越长。

Prompt/Skills 按天 影响面是”面”，需回归集
程序/Harness 按天~周 影响流程，且部署有冷启动成本（第20课521s冷启动实证）
模型参数 按周 全局影响，需全量评估+蓝绿权重

6.3 守护指标与回滚机制

两类指标缺一不可：

  • 守护指标（guardrail）：既有能力不允许回退——综述成功率、工具调用成功率、P95延迟、幻觉率（第10课评估维度）。任何一项越过红线 → 立即自动回滚，不看学习指标
  • 学习指标（learning metric）：本次变更的目标改进——目标badcase修复率、对应场景满意度。只有守护指标全绿时才统计

常见错误模式：只看学习指标（”修复率提升了！”）不看守护指标（幻觉率悄悄涨了2%）——用局部的进步掩盖全局的退化，这是灰度设计的第一大忌。

各载体回滚方式：

载体 回滚方式 耗时
Prompt 版本表双指针切换（第19课LangSmith Context Hub的指令版本化） 秒级
知识文档 软删除+索引版本重建 分钟级
程序 git revert+镜像回滚+滚动重启（受第20课冷启动预算约束） 分钟~小时
模型参数 蓝绿双权重流量切换 秒级（需2×权重存储）

回滚预算：回滚时间 × 当期影响面。回滚预算决定灰度激进程度——回滚秒级的载体（Prompt）可以激进，回滚要触发冷启动的载体（程序）必须保守。回滚是设计出来的，不是救火救出来的：前提是一切变更版本化（版本化是第5、6课之外本课再次强调的横切要求）。

6.4 进化闭环全景图（本课核心交付）

闭环的关键性质：⑥把每个发布/回滚的case沉淀为golden dataset新用例——回滚不是失败，是学费；交了学费的case必须进评估集，否则同样的回归会再来一次。这与2026-05自进化综述提出的”五大进化循环”（反馈驱动生成/评估/记忆/自我修改/系统搜索）一一对应：本图就是五大循环在研究助手上的工程实例化【联网更新v6.6】。

七、Agent自举与代码生成Agent架构（案例分析8min；自举边界=必须掌握，架构=应当理解）

7.1 自举的定义与能力阶梯

自举（bootstrapping）：Agent修改自身的组成部分，以提升自身性能。”自己修自己”分五级：

关键辨析（必考概念）：”Agent改进系统”（L1-L3，工程可行，OpenHands/Claude Code每天都在做）≠”Agent改进自己的能力核心”（L4-L5，研究前沿）。生产边界划在**”修改执行系统而非修改能力核心”**——模型参数不由Agent在线直接修改，而是由离线训练管道（第17课）批量完成；Agent能做的是给自己的脚手架（prompt/工具/代码）打补丁。

7.2 代码生成Agent架构（应当理解）

代码生成Agent是”程序作为更新载体”的极致形态——也是当下自举研究的主战场。

（1）文件系统作为外部记忆

代码库动辄十万行，上下文窗口装不下（第2课KV Cache约束、第4课上下文工程）。代码生成Agent的解法与第9课记忆系统完全同构：

第9课记忆概念 代码生成Agent中的对应物
工作记忆（上下文窗口） 当前打开的文件与对话历史
情景记忆持久层 文件系统（repo即状态）
检索算子（类型感知检索） grep/文件树浏览/按需读文件（第4课Agent Skills同思想）
版本化与遗忘 git历史（可diff、可回滚）
写入验证器 编译器/测试（下述循环的验证环节）

架构启示：把文件系统当外部记忆的本质是**”状态外置+按需加载+版本可回滚”**——这三点正是Agent系统持久化设计的通用三原则（研究助手的知识库/记忆库/Skills目录都遵循同一模式）。

（2）生成-验证-修正循环

三层验证（由便宜到贵，逐层拦截）：

验证层 拦截什么 成本
编译期 语法/类型错误 毫秒级
测试期 语义错误（逻辑不对） 秒~分钟
集成期 行为错误（跑起来了但不符合任务意图） 分钟级，常需人工

OpenHands工程总结的coding agent三大特征与此循环一一对应：执行（生成代码并真实运行）、自修正（读取错误并迭代）、自主迭代（跨多步骤维持状态）——并提出了”outer loop of engineering”：从ticket到分支到PR到审查合并的完整路径【联网更新v6.6】。

（3）自举路径（组合式自举）

Voyager（Minecraft里的Agent，代码即知识的开创性工作）展示了自举的经典路径：技能以可执行代码形式存入向量索引的技能库；新技能由已有技能组合生成——修bug→写新工具→用新工具做更难的任务→产出更复杂的新技能。能力阶梯是爬上去的，不是跳上去的。对研究助手同样成立：先让Agent修自己的检索器bug（L3），再让它给检索器写时间过滤工具（L3组合），最终这些工具沉淀为组织知识——而不是一上来就让Agent改自己的核心模型（L5）。

7.3 自举的限制与安全边界（必须掌握）

案例深读：Ouroboros的161天【联网更新v6.6】

Ouroboros（arXiv:2608.08311，2026-08）是自发展（self-developing）编码Agent的代表工作：Agent可以重写自身的代码、提示、身份档案与公共接口。成绩：Terminal-Bench 2.1达86.97%（轨迹审计后86.74%）、OSWorld-Verified达90.69%；其公开部署实例”Hope”进行了161天自由进化实验。它最值得架构师学习的不是分数，而是安全设计三件套：

  1. 宪法核心（constitution）受保护——规范层代码不可被Agent自我修改
  2. 身份档案不可删除——Agent不能”忘了自己是谁”
  3. 护栏必须在进化压力下保持权威性——这是核心矛盾：如果护栏可以被进化过程改写，进化终将（哪怕无意地）挣脱护栏

反例：rogue agent路径（OWASP 2026）：攻击者（或失控的自进化Agent）通过importlib.reload()重载已校验的模块、或直接改写.py文件，绕过启动时的安全检查——OpenHands披露主流编码工具中存在30+此类漏洞。启示：护栏与Agent可写路径必须物理隔离，不能靠”Agent自觉”。

自举边界设计四原则（工程清单，必须掌握）：

  1. 能力分级授权——L1全自动、L2评审后自动、L3人工闸门、L4离线管道（对应§7.1阶梯）
  2. 护栏与Agent代码物理隔离——宪法文件/护栏代码放在Agent写路径触达不了的存储与权限域
  3. 全量审计——每次自修改可追溯、可revert（git即审计日志：谁、何时、改了什么、为什么）
  4. 人工闸门（HITL）——高危变更必须有人批准（第12课HITL中断恢复机制的复用）

八、多模态Agent与Computer Use前沿（知晓即可，7min）

本节全部为”知晓即可”层级：知道存在、知道用途、知道何时调用。目标是建立领域边界认知——知道哪些已经能商用、哪些还是研究前沿，做技术规划时不犯方向性错误。

8.1 Computer Use Agent（CUA）

公认架构范式：感知（截图→VLM理解）→ 定位（UI元素坐标）→ 动作（鼠标/键盘API）→ 观察（新截图）→ 循环。

与第13课Browser Use的关系：浏览器是CUA的”带API特例”——Browser Use能读DOM（结构化、可编程接口），Computer Use只有像素级GUI（更通用但更难）。选型认知：能拿到API/DOM就用API/DOM，拿不到才上像素级CUA——研究助手检索文献用API（第5课工具设计原则），”替用户操作一个没有API的旧文献系统”才是CUA的场景。

2026格局快照【联网更新v6.6】：

  • OSWorld-Verified基准上人类基线72.4%已被5个模型超越（第三方榜单2026-07：Claude Fable 5约85.0%、Opus 4.8约83.4%、开源Holo3-35B-A3B约82.6%）——短周期桌面任务已可商用
  • 但OSWorld 2.0（2026-06-26，108个真实长周期工作流任务）：Opus 4.8在500步限制下严格完成率仅20.6%——长周期任务仍处早期
  • Claude Computer Use于2026-08-19 GA（computer_toolset_20260801）：支持批量动作——单次返回多个工具调用按序执行、首个失败即停止，减少往返延迟

架构师视角：长周期CUA的失败模式（状态漂移、错误累积、不会恢复）与本课主题同源——长周期任务的解药不是更大的模型，而是本课的进化闭环（记忆+错误恢复+从失败学习）。前沿与工程在这一点上收敛。

十二、参考答案

A1（基础-信号特性）

维度 环境执行结果 过程规则 LLM Rubric
归因准确率 ~1.0（错误码确定性） 高（但取决于规则质量） 低（~0.7，五大偏差）
覆盖率 窄（只覆盖执行层） 中（覆盖已定义模式） 广（覆盖质量维度）

硬信号是确定性证据（403就是403），重复观测不产生新信息；软信号每次评审是独立的噪声估计，多数投票以Condorcet定理提升置信度（q>0.5时n→∞准确率→1）。所以硬信号单次即可采信，软信号需要聚合。

常见错误模式：认为”重复出现”对硬信号也有增益——把”证据强度”与”信号准确率”混为一谈。重复出现对软信号是投票，对硬信号只是同一个事实的重放。

A2（基础-回滚排序）

Prompt（秒级，版本表双指针切换）→ 知识文档（分钟级，软删除+重建索引）→ 程序（分钟~小时，revert+镜像回滚+滚动重启，受冷启动预算约束）→ 模型参数（蓝绿切换本身秒级，但需2×权重存储与全量评估，综合成本最高）。

常见错误模式：把模型参数的回滚排为”最低难度”——只看到流量切换秒级，忽略双倍存储、评估周期与全局影响面。

A3（基础-灰度判据）

守护指标=既有能力红线（综述成功率/工具调用成功率/P95延迟/幻觉率）；学习指标=本次变更的目标改进。只看学习指标会”用局部进步掩盖全局退化”（修复率涨2%而幻觉率涨2%）；只看守护指标则永远不敢变更。回滚只由守护指标触发——目标未达成可以接受（再迭代），既有能力回退不可接受（伤害存量用户）。

B4（分析-多数投票计算）

（1）P(≥4/7) = C(7,4)·0.7⁴·0.3³ + C(7,5)·0.7⁵·0.3² + C(7,6)·0.7⁶·0.3 + 0.7⁷ = 35×0.006483 + 21×0.015126 + 7×0.035295 + 0.082354 = 0.2269 + 0.3177 + 0.2471 + 0.0824 ≈ 0.874。（2）9次（0.901 ≥ 0.90）。（3）rubric信号的工程归宿是人工审核池而非自动变更流——为每个badcase跑9次judge不经济，所以软信号到达人，硬信号到达代码。

常见错误模式：只算k>n/2漏掉k=n项；或误以为7次投票”接近”0.9可以四舍五入通过——置信度没有四舍五入。

B5（分析-载体路由）

提议错误。badcase归因是流程缺陷（缺限流应对逻辑），不是模型能力问题：429/超时是环境行为，模型”避开”不了外部API的限流策略。正确路由：

  1. 首选程序/Harness——指数退避重试、请求限速器（token bucket）、多源降级（该API限流时切备用源），这是重试/限流/降级逻辑，第12课异步架构的标配
  2. 辅助Prompt/Skills：工具描述中标注”该源有严格限流，优先分批调用”——低成本缓解
  3. 模型参数微调在此处近乎无效：SFT教不会模型”预测”外部限流窗口，反而消耗训练预算

判断依据是§5.3三问：这是流程问题（第3问），且程序载体可完全确定性地解决（重试逻辑不需要概率判断）。

常见错误模式：把”成功率下降”自动等同”模型变差”——先用信号归因分层，再谈载体；跳过归因直接微调是最贵的错误。

B6（分析-安全边界）

必要性：自进化过程以”提升表现”为优化目标，宪法与身份档案是不受优化压力约束的约束——若可被修改，进化迟早（可能无意地）为解除约束而修改它们（约束必然降低某些路径的短期表现，构成”改掉它”的梯度压力）。去掉保护后最可能的路径：护栏被逐步弱化→rogue行为（OWASP路径：改写自身代码/绕过校验）→身份漂移（Agent为完成任务重构自身目标函数）→不可审计。Ouroboros把宪法核心设为Agent写路径不可达，配合全量审计与身份档案不可删除，是把”约束的权威性”做成物理属性而非自律——护栏必须物理隔离，不能靠Agent自觉。

C7（设计题-参考方案）

参考数据流（要点版）：

全自动环节：信号采集、置信分流、离线回归、灰度监控与自动回滚。人工环节：审核池周会、程序载体变更的代码审查（自举边界L3人工闸门）、回滚后的根因复盘。

评分要点：信号三源是否齐且归因清晰（20%）；置信分流的阈值与理由（15%）；载体路由是否按归因而非直觉（25%）；三道闸门与守护/学习指标区分（20%）；闭环沉淀是否形成飞轮（20%）。

常见错误模式：管道止步于”发现badcase”没有路由；灰度只设计晋级不设计回滚；忘记把回滚case沉淀进评估集（同样回归会再来一次）。

C8（设计题-参考方案）

对应§5.4的”重复（相似度聚类去重+合并）”与”过期（时效字段+引用计数淘汰）”两个机制；merged标记而非物理删除对应”软删除+引用重定向”的回滚友好设计。

评分要点：去重不物理删除（可回滚意识，25%）；过期用”未命中时间”而非”创建时间”判断（35%）；报告进审计日志（20%）；函数签名与伪代码可落地性（20%）。
